# Business Process Map — 관리자 매뉴얼

> 이 매뉴얼은 **시스템 관리자(sysadmin)**를 위한 문서입니다. 관리자 콘솔, 운영 업무, 그리고 모든 맵에 걸쳐 sysadmin이 갖는 추가 권한을 다룹니다. **사용자 매뉴얼**(맵 편집 · 사용 안내)을 먼저 읽으세요 — 그 내용 전부가 관리자에게도 적용됩니다.

---

## 1. Sysadmin 역할

### 지정 방식

Sysadmin은 DB에 사용자별로 저장되지 **않습니다** — 백엔드가 기동 시 읽는 **`BPM_SYSADMINS`** 환경변수(로그인 ID 콤마 목록)로 결정됩니다.

```
# backend .env
BPM_SYSADMINS=admin.sys,jane.doe
```

- 인증이 **꺼진** 상태(개발 기본값)에서는 사실상 모든 사용자가 sysadmin입니다.
- `DEV_ENFORCE_PERMISSIONS=true` 또는 실제 Keycloak 인증이 켜지면 `BPM_SYSADMINS`에 등록된 ID만 sysadmin입니다.
- 권한 콘솔에서 해당 사용자에게 **Sysadmin** 태그가 표시되며 *env 관리*로 안내됩니다 — UI에서는 켜고 끌 수 없습니다.
- 서버가 **ldap 인증 모드**일 때는 로컬 계정 화면(7장)의 계정별 **Sysadmin 토글**로도 부여할 수 있습니다 — 이 부여는 ldap 모드에서만 효력이 있습니다. env로 지정된 사용자는 "환경변수로 지정됨"으로 표시되며 화면에서 끌 수 없습니다.

### Sysadmin이 여는 것들

- 모든 맵에서 **Owner로 간주**됩니다 — 어느 맵이든 협업자·결재자·공개 범위·버전·삭제를 관리할 수 있습니다.
- **강제 체크아웃** — 다른 사용자의 활성 편집 잠금을 가져올 수 있는 유일한 역할입니다.
- **설정** 아래 관리자 전용 콘솔: 공지, 임직원·부서, 프레임워크, 데이터베이스, 승인 큐.
- 운영 권한: 유저그룹 승인, 피드백 답변·상태 변경, 전체 휴지통, 매뉴얼 게시.

## 2. 관리자 콘솔 지도

모든 관리자 화면은 **설정** 아래에 있습니다. sysadmin으로 로그인하면 좌측 레일에 추가 카테고리가 보입니다:

| 콘솔 | 위치 | 역할 |
| --- | --- | --- |
| **공지(Notices)** | 설정 → 콘텐츠 | 공지 작성·수정·삭제 |
| **매뉴얼(Manual)** | 설정 → 콘텐츠 | 인앱 매뉴얼 편집·게시 (11장 참고) |
| **지식기반(Knowledge base)** | 설정 → 콘텐츠 | AI 컨설턴트가 인터뷰에서 인용할 조직 문서 업로드 (12장 참고) |
| **AI 챗(AI chat)** | 설정 → 콘텐츠 | 대화 보존 상한 설정·채팅 로딩 팁 관리 (12장 참고) |
| **AI 프롬프트(AI prompts)** | 설정 → 콘텐츠 | 내장 AI 프롬프트 오버라이드 관리 (12장 참고) |
| **임직원(Employees)** | 설정 → 조직 | 조직 디렉터리 테이블 — HR 웹훅 전체 동기화, sysadmin 태그, CSV 내보내기 |
| **부서(Departments)** | 설정 → 조직 | 조직 기준 부서 테이블, 부서 재지정, CSV 내보내기 |
| **로컬 계정(Local Accounts)** | 설정 → 조직 | ldap 인증 모드 전용 — 외부 컨설턴트용 로컬 로그인 계정 관리 (7장 참고) |
| **Framework(업무체계)** | 설정 → 프레임워크 | 업무체계 카테고리 관리·JSON 임포트 — 시범 단계 (13장 참고) |
| **테이블(Tables)** | 설정 → 데이터베이스 | 읽기 전용 DB 브라우저(로그인 기록 포함), 서버 CSV 내보내기 |
| **배치 작업(Batch jobs)** | 설정 → 데이터베이스 | DB 백업·HR 동기화의 최근 실행 상태(성공/실패) 확인 |
| **승인 큐(Approval Queue)** | 설정 → 승인 | 전 맵 대상 대기 요청 |
| **대시보드(Dashboard)** | 설정 → 분석 | 실 DB 기반 운영 지표 — 열람 권한을 다른 사람에게 위임 가능(8장) |
| **그룹(Groups)** | 설정 → 그룹 | 그룹 요청 승인, 전체 그룹 조회 |
| **삭제 예정** | 설정 → 휴지통 | 소프트 삭제된 모든 맵·그룹 |

## 3. 공지 관리

모든 사용자의 **공지사항** 탭에 표시되는 공지를 관리합니다.

1. **설정 → 콘텐츠 → 공지**로 이동합니다.
2. **새 공지**: 제목, 중요도(**중요** / 일반), 게시 기간(시작–종료 또는 **종료일 없음**), **마크다운** 본문.
3. **게시 시 전체 알림**을 체크하면 모든 사용자의 알림함으로 푸시됩니다.

- 사용자는 게시 기간이 유효한 공지만 봅니다. 관리자 목록에는 전부 표시됩니다.
- 관리자 공지 목록은 **CSV 내보내기** 버튼으로 전체를 내려받을 수 있습니다 — 화면과 동일 컬럼, Excel 호환(BOM), 수식 인젝션 가드 적용.
- 공지 수정은 즉시 반영됩니다. **삭제는 하드 삭제**입니다 — 휴지통 없이 즉시 영구 삭제되며 복구할 수 없습니다(맵·그룹의 7일 휴지통과 다름). 단, 게시 시 전체 알림을 켰다면 그때 이미 발송된 벨 알림은 공지를 삭제해도 그대로 남습니다.

> **팁:** 공지 본문은 이 매뉴얼과 같은 마크다운 뷰어로 렌더됩니다 — 헤딩, 표, 코드블록, `#태그` 필이 모두 동작합니다.

## 4. 피드백 관리

사용자 피드백(버그 / 제안 / 질문 / 기타)은 발신 시점의 화면과 열려 있던 맵 정보와 함께 **피드백** 페이지로 들어옵니다.

- **상태 변경**과 **답변**은 sysadmin만 할 수 있습니다.
- 항목을 처리 단계에 따라 이동시키세요. **완료** 처리하면 완료 시각이 기록되고 **추가 답변이 잠깁니다**.
- 사용자는 자기 제출 건을 지켜보고 있으므로, 상태 변경과 답변은 피드백 페이지에서 바로 보입니다. 다만 **알림은 자동으로 가지 않습니다** — 아래 버튼으로 직접 보냅니다.

### 작성자에게 알림 보내기

상세 창(목록 행 클릭)에서 두 가지 알림을 **관리자가 직접** 보냅니다. 버튼을 누르면 확인 창이 뜨고, 보내면 토스트로 결과를 알려 줍니다.

- **알림 보내기**(답글 영역 오른쪽 아래) — 답글을 저장한 뒤 누르면 "답글이 등록되었다"는 알림이 갑니다. 답글을 고쳐 **다시 보낼 수 있습니다**. 완료 처리된 건에서도 보낼 수 있습니다.
- **상태변경 알림**(하단 상태 세그먼트 오른쪽) — 상태를 바꾼 뒤 누르면 바뀐 상태가 알림으로 갑니다. **피드백당 한 번만** 보낼 수 있고, 보낸 뒤에는 버튼이 잠기며 체크 표시가 붙습니다.
- 보낸 이력은 상세 창 아래 메타에 **"알림 발송 〈시각〉"** 행으로 남아 이전에 보냈는지 바로 확인됩니다.
- 버튼이 **회색으로 비활성**이면 이유가 툴팁에 뜹니다 — 본인이 작성한 피드백(보낼 대상 없음)·답글 미저장·상태변경 알림 기발송.

### 노트 (진행 메모)

- 목록 오른쪽 끝 노트 버튼으로 열리며, **누구나** 노트를 남길 수 있습니다(권한 제한 없음). 시간순 로그로 쌓입니다.
- **수정**은 작성자 본인만 — 고치면 직전 본문이 **이력으로 보존**되고, "수정됨" 배지를 눌러 이전 내용을 볼 수 있습니다.
- **삭제는 아카이브**입니다(작성자 또는 관리자). 기본 목록에서 숨겨질 뿐 기록은 남고, "아카이브 보기"로 확인합니다.
- **영구 삭제**는 **설정 → 데이터베이스 → 테이블 → `feedback_notes`**에서 **아카이브 노트 삭제** 버튼으로만 가능합니다(수정 이력까지 함께 지워지며 되돌릴 수 없습니다).

## 5. 유저그룹 관리

그룹 생성은 요청 기반입니다. 누구나 그룹을 요청할 수 있지만, sysadmin이 승인해야 **활성** 상태가 됩니다.

- 대기 중인 요청은 **승인 큐**(및 그룹 대기 목록)에 나타납니다. 이름, 멤버(최소 2명), 매니저(최소 1명)를 확인하고 승인/반려하세요.
- Sysadmin은 비활성·삭제된 그룹을 포함해 **모든 그룹**을 볼 수 있습니다. 일반 사용자는 자기가 속한 그룹만 봅니다.
- 삭제된 그룹은 **7일간** 휴지통에 있다가 영구 삭제됩니다. **설정 → 휴지통**에서 복구하세요.

## 6. 전체 승인 큐

**설정 → 승인 → 승인 큐**는 전 맵의 대기 요청을 한곳에 모읍니다:

- **그룹 생성** 요청.
- **권한 강등** 요청(편집자 제거·강등).
- **공개 범위 변경** 요청(공개 ↔ 비공개).
- **체크아웃 이전** 요청(다른 사용자의 활성 편집 잠금 이전).

각 항목에 요청자와 맥락이 표시되며 승인 / 반려(사유 필수)로 처리합니다. 맵 단위 요청은 해당 맵의 결재자도 처리할 수 있습니다 — 이 큐는 놓친 요청이 없는지 확인하는 전체 뷰입니다.

> 이 밖에 **맵 이름 변경**과 **서브프로세스 등록 요청**은 결정권자가 **맵 오너**인 요청입니다 — sysadmin은 전 맵의 오너 권한을 가지므로 Inbox(승인 대기)에서 모든 맵의 해당 카드를 대신 처리할 수 있습니다. 서브프로세스 등록은 **지정 폼 저장이 곧 승인**이며, 게시본이 없는 맵은 지정할 수 없습니다.

## 7. 디렉터리와 임직원

**설정 → 조직 → 임직원**은 담당자·협업자·결재자 선택에 쓰이는 조직 디렉터리를 보여줍니다.

- 인원·조직도의 소스는 **n8n HR 웹훅**입니다(구 AD 동기화 대체) — 전체 동기화가 임직원과 **부서(departments) 테이블**을 함께 갱신하며, AD(LDAP)는 **직급(title) 보강 전용** 패스로 축소되었습니다.
- 테이블에 조직 단계, 재직 상태(active/inactive), 사용자별 sysadmin 태그가 포함됩니다.
- **전체 동기화** — 임직원 탭의 동기화 버튼(라벨은 **AD 전체 동기화**로 유지)으로 수동 실행합니다. 실행 중에는 버튼에 스피너와 **동기화 중…**이 표시되고, 동기화와 후속 목록 재조회가 끝날 때까지 비활성입니다. 완료되면 scanned·upserted·deactivated·deleted·skipped 요약이 표시됩니다. 연속 실행은 5분 간격으로 제한됩니다.
- **자동 동기화** — 내장 스케줄러가 `HR_SYNC_INTERVAL_HOURS` 주기(기본 24시간, 0 = 끔)로 전체 동기화를 반복합니다. 로그인한 사용자는 이와 별개로 하루 1회 1인 동기화됩니다.
- **퇴직자** — HR에서 inactive로 내려온 사람은 삭제되지 않고 **active=false**(status: inactive)로 표시되며, 피커·디렉터리에서 자동 제외됩니다.
- **동기화 안전장치** — ① **드라이런 프리뷰**: `POST /api/employees/sync-preview`(sysadmin API)가 DB 변경 없이 갱신·비활성·삭제 예정 건수와 샘플 목록을 반환합니다 — 첫 이행이나 대규모 조직개편 전에 확인하세요. ② **삭제 비율 상한**: 한 번의 동기화가 관리 행의 `HR_SYNC_DELETE_CAP_PCT`(기본 20%)를 초과해 삭제하려 하면 동기화 전체가 중단됩니다.
- 한글 이름·한글 부서는 HR 웹훅이 직접 채우므로 구 임포트 도구(한글 이름·부서 정보 임포트)는 제거되었습니다. email 필드도 모델에서 제거되어 디렉터리는 이메일을 저장하지 않습니다.
- 에디터의 담당자 선택기는 이 디렉터리를 참조합니다 — 디렉터리가 오래되면 선택기에서 사람이 빠집니다.
- **CSV 내보내기** — 임직원·부서 테이블의 **CSV 내보내기** 버튼이 화면과 동일한 컬럼으로 전체 행을 내려받습니다. Excel 호환(BOM 포함)이며 수식 인젝션 가드가 적용됩니다.

### 부서와 부서장

**설정 → 조직 → 부서**는 조직 기준인 **departments 테이블**을 보여줍니다(구 dept_info 제거) — 조직도와 부서 경로 해석이 모두 이 테이블 기반입니다.

- 부서 목록(이름·한글 부서·인원수)을 확인하고 CSV로 내보낼 수 있습니다.
- **부서장 판정** — EDW 직책(FRNM) 웹훅으로 수집한 직책으로 부서장을 판정해 부서장 체인에 **Manager** 태그로 표시합니다. 직책 패스는 EDW 웹훅(`N8N_POSITION_URL`)과 AD(사번 매핑)가 모두 설정된 경우에만 실행됩니다.
- **노출 직책(Exposed positions)** — 임직원 탭의 카드에서 수집된 EDW 직책 중 앱에 직책으로 표시할 항목을 체크해 저장합니다(기본: 그룹장·파트장·팀장·센터장). env가 아니라 화면에서 저장하는 앱 설정입니다.
- **부서 재지정(Missing departments)** — 조직개편으로 사라진 부서 경로가 맵 권한·그룹 멤버·오우닝 부서에 아직 참조로 남아 있으면 부서 탭에 표시되며, 각각을 현재 부서로 재지정합니다.

### 로컬 계정 (ldap 모드 전용)

**설정 → 조직 → 로컬 계정** 탭은 서버 인증 모드가 **`ldap`일 때만** 나타납니다. 디렉터리(HR) 계정이 없는 **외부 컨설턴트**에게 아이디/비밀번호를 발급하는 화면입니다.

- **계정 생성** — 로그인 아이디·이름·부서 코드(선택)·비밀번호를 입력합니다.
- **로그인 순서** — 로그인 시 로컬 계정을 먼저 확인하고, 없으면 AD(사내 계정) 인증으로 폴백합니다. 로그인 시도는 **5분당 5회**로 제한됩니다.
- **관리** — 계정별로 **비밀번호 재설정**, **비활성(Deactivate) / 재활성**, **삭제**(영구 — 복구 불가)를 지원합니다. 프로젝트가 끝난 컨설턴트 계정은 삭제 전에 우선 비활성으로 차단하세요.
- **Sysadmin 토글** — 로컬/AD 계정에 sysadmin을 부여합니다(1장 참고 — ldap 모드에서만 효력).
- 토큰 수명·시크릿 교체(전체 세션 무효화) 등 운영 계약은 `docs/deploy/deploy.md` §2.1을 참고하세요.

## 8. 데이터베이스 뷰어와 운영 대시보드

**설정 → 데이터베이스 → 테이블**은 서버 측 페이징·정렬·필터를 지원하는 읽기 전용 DB 브라우저입니다.

- 데이터 확인 용도로만 사용하세요 — 쓰기는 불가능합니다.
- **CSV 내보내기**(sysadmin 전용) — 헤더의 **CSV 내보내기** 버튼이 현재 정렬·필터를 그대로 적용한 **전체 행**을 서버에서 스트리밍으로 내려받습니다(페이징 없음). Excel 호환(BOM)·수식 인젝션 가드는 관리자 테이블 내보내기와 동일합니다.
- **로그인 기록**은 `login_records` 테이블에 있습니다: 사용자당 하루 한 행, 그날 첫 인증 시 기록됩니다. "누가 언제 썼는지"의 감사 뷰입니다.
- **알림 보존**: `notifications`는 1인당 **최근 100건**만 유지되는 고정 정책입니다(조정 불가) — 초과분은 새 알림 발생 시점에 읽음 여부와 무관하게 오래된 것부터 자동 삭제됩니다.

### 알림 기간 삭제 (퍼지)

**테이블**에서 `notifications`를 선택하면 헤더에 기간(from–to) 입력과 **기간 내 삭제** 버튼이 나타납니다.

1. 삭제할 기간을 고르고 **기간 내 삭제**를 클릭합니다.
2. **미리보기 모달**이 그 기간의 알림을 내용(유형·메시지)별로 묶어 수신자 수와 발생 기간을 보여줍니다 — 기본은 **전체 선택**.
3. 원치 않는 묶음은 체크 해제한 뒤 확정하면, 선택한 묶음의 기간 내 전 수신자 행이 **하드 삭제**됩니다. **복구 불가** — 신중히 사용하세요.

### 배치 작업 상태 (설정 → 데이터베이스 → Batch jobs)

**DB 백업**과 **인원(HR) 동기화**의 최근 시도를 잡(job)별로 보여줍니다 — 마지막 **성공**과 마지막 **실패**의 시각·요약이 각각 남아, 밤새 돈 배치가 정상이었는지 아침에 바로 확인합니다. 실패 행이 최근 성공보다 나중이면 조치가 필요하다는 신호입니다.

### 일일 DB 자동 백업 (운영 서버)

서버 compose에는 **`db-backup` 사이드카**가 포함되어 있습니다:

- 매일 **04:00 KST** 이후 하루 1회 + 컨테이너 기동 직후(오늘자 덤프가 없으면) 1회 `pg_dump`를 뜹니다.
- 덤프는 `pg_restore --list` **검증을 통과한 경우에만 확정**되고, 결과가 배치 작업 상태 탭에 기록됩니다.
- 저장 위치는 호스트 `${BACKUP_DIR}`(기본 `./backups`), 보존은 `${BACKUP_RETENTION_DAYS}`(기본 **14일**) — 초과분은 자동 삭제됩니다.
- 현재는 **서버 디스크에만** 보관됩니다 — 디스크 장애에는 무방비이므로 주기적인 오프서버 사본을 권장합니다. **복구 절차(덮어쓰기·신규 서버)는 `docs/deploy/backup.md`** 런북을 따릅니다.

### 대시보드 (설정 → 분석)

실 DB 기준 운영 지표를 한눈에 보여줍니다:

- **운영(Operations)** — 전체 맵·게시본·진행 중·휴지통 수, 열린 댓글, 미읽음 알림, 체크아웃 이전 요청.
- **버전 상태(Version status)** — 초안·검토대기·승인·게시·만료 버전 분포.
- **부서별 도입률(Adoption by department)** — 맵을 보유한 부서 비율. 분모로 셀 부서는 **커버리지(Coverage)** 사이드바에서 관리자가 고릅니다.
- **로그인·활동**, **누적 증가**(맵·버전 생성 추이) — 기간 필터(7일 / 1개월 / 3개월 / 사용자 지정)로 시계열을 조정합니다(현재 상태 지표는 기간 필터의 영향을 받지 않습니다).
- **최근 버전 이벤트**, **AI 사용량**(7일·30일 호출 수, 상위 맵).

**대시보드 열람 권한**은 sysadmin이 위임할 수 있습니다 — 대시보드 우측 **접근(Access)** 사이드바에서 사람·부서·유저그룹에 **권한 부여**하면 sysadmin이 아니어도 대시보드를 열 수 있습니다(sysadmin은 항상 열람 가능). 권한이 하나도 없으면 sysadmin만 봅니다.

## 9. 휴지통과 복구

맵·그룹 삭제는 **소프트 삭제**입니다 — 휴지통으로 이동하고 **7일** 후 영구 삭제됩니다.

- 소유자는 **설정 → 삭제 예정**에서 자기 맵만 보지만, sysadmin은 **전원의 것**을 봅니다.
- **복구**하면 맵이 버전·노드·권한 그대로 돌아옵니다.
- 7일이 지나면 영구 삭제되어 되돌릴 수 없습니다.
- **즉시 영구삭제(sysadmin 전용)** — 휴지통 행의 즉시 삭제 버튼으로 7일 보존을 기다리지 않고 바로 제거할 수 있습니다. 휴지통에 있는(소프트 삭제된) 맵만 대상이며, **복구할 수 없으니** 신중히 사용하세요.

## 10. 버전 워크플로 — 관리자 권한

사용자 매뉴얼의 워크플로 내용에 더해:

- **강제 체크아웃** — 보유자가 부재할 때 활성 편집 잠금을 가져옵니다. 이전 보유자의 미저장 작업 맥락이 사라지므로 신중히 사용하세요. 유휴 잠금은 이미 30분 후 자동 해제됩니다.
- **어디서든 결정** — 실질 Owner이므로 어느 맵에서든 승인 요청·게시를 하고 체크아웃 요청·이전을 처리할 수 있습니다. 단, **회수(Withdraw)**는 예외입니다 — 검토대기·승인됨 버전은 **제출자만** 회수할 수 있고, 반려된 버전만 맵 오너·sysadmin이 회수할 수 있습니다.
- **결재자 재지정** — 활성 결재자가 없는 맵(예: 유일한 결재자 퇴사)은 맵 설정 → 결재자의 강제 재지정 플로로 새 결재자를 지정합니다.
- 게시 규칙 유의: 게시하면 직전 게시 버전이 #만료됨 처리되며, 이는 승인에 다시 들어갈 수 없는 최종 상태입니다. 다시 진행하려면 **재게시**로 새 초안을 만드세요.

## 11. 이 매뉴얼 게시하기

**/manual**은 여러 문서를 담을 수 있습니다(공지사항처럼). **설정 → 콘텐츠 → 매뉴얼**에서 관리합니다:

1. **문서 목록**에서 기존 문서를 클릭해 수정하거나 **새 문서**로 추가합니다. 행의 휴지통 버튼으로 삭제합니다.
2. 포맷(**마크다운**/**HTML** — HTML은 렌더 전에 sanitize)과 **언어(한국어/English)**를 고릅니다. 뷰어에는 상단 한/영 토글에 맞는 언어의 문서만 목록에 뜹니다.
3. 편집기에 직접 쓰거나, **.md 업로드**로 파일을 불러오거나, **배포본 불러오기**로 빌드에 포함된 원문에서 시작합니다.
4. **미리보기**는 사용자가 보게 될 화면 그대로 렌더하고, **게시**하면 즉시 /manual에 반영됩니다.

- 목록 제목은 저장 시 본문 **첫 헤딩에서 자동 추출**됩니다.
- 한/영 문서를 짝지어 같은 순서로 올리면, 뷰어에서 언어를 전환해도 같은 순번의 문서가 열립니다.
- 등록된 문서가 없으면 뷰어는 빌드에 포함된 기본 매뉴얼을 보여줍니다.
- **번들 fallback** — 한 번도 게시된 적이 없으면 빌드에 포함된 `backend/app/manual.md`가 제공되고, 뷰어에 갱신 시각 대신 **배포 포함본** 뱃지가 표시됩니다.
- 같은 게시를 sysadmin API로도 할 수 있습니다:

```
PUT /api/manual
{ "format": "markdown", "content": "<마크다운 전문>" }
```

뷰어는 `##`·`###` 헤딩으로 목차를 만들므로 문서를 그 구조로 작성하세요. 렌더러는 헤딩, 평면 리스트, 표, 펜스 코드블록(호버 복사), 인라인 코드(클릭 복사), 인용, 링크, 굵게/기울임, `#단어` 필을 지원합니다 — 이미지와 raw HTML은 렌더되지 않습니다.

## 12. AI 챗 설정

**설정 → 콘텐츠 → AI 챗** (sysadmin 전용). 재배포 없이 즉시 적용됩니다.

- **대화 저장**: AI 챗 대화는 항상 서버에 저장됩니다(사용자·맵 단위로 귀속되며 본인만 조회할 수 있습니다) — 켜고 끌 수 있는 옵션이 아닙니다. `ai_chat_sessions`(대화)·`ai_chat_messages`(메시지) 테이블에 쌓이며 테이블 뷰어에서 조회할 수 있습니다.
- **보존 상한**: 맵당 대화 수·대화당 메시지 수·마지막 활동 후 보관 일수를 관리자가 조정합니다. 초과분은 오래된 것부터 자동 정리됩니다.

| 키 | 기본값 | 범위 |
| --- | --- | --- |
| `ai_chat_max_sessions_per_map` | 20 | 1–200 |
| `ai_chat_max_messages_per_session` | 200 | 10–2000 |
| `ai_chat_retention_days` | 180 | 7–3650 |

- **채팅 로딩 팁**: 이전 대화를 불러오는 동안 채팅에 노출되는 기능 팁을 관리합니다. 한 줄당 팁 1개(팁당 200자, 최대 50개). **모두 지우고 저장하면 기본 20종으로 복원**됩니다.

### 지식기반 (설정 → 콘텐츠 → Knowledge base)

**AI 컨설턴트(인터뷰)가 인용할 조직 문서**를 올리는 라이브러리입니다 — SOP·가이드 등을 업로드하면 인터뷰 답변의 근거로 활용됩니다. 지원 형식은 pdf·docx·xlsx·txt·md(파일당 최대 20MB)이며, **Upload**로 추가하고 **Refresh**로 목록을 갱신합니다.

### AI 프롬프트 (설정 → 콘텐츠 → AI prompts)

AI 기능(챗·인터뷰·드래프터 등)이 쓰는 **내장 프롬프트를 화면에서 오버라이드**합니다 — 저장하면 재배포 없이 즉시 적용되고, 비우면 빌드에 포함된 기본 프롬프트로 돌아갑니다. **오버라이드가 있는 동안 코드의 기본 프롬프트 개선은 반영되지 않으니**, 배포 후에는 오버라이드가 아직 필요한지 주기적으로 점검하세요.

## 13. Framework(업무체계) 관리

> 업무체계(Framework)는 아직 **시범 단계**입니다 — 화면 구성과 데이터가 바뀔 수 있습니다.

**설정 → 프레임워크 → 카테고리·임포트**(sysadmin 전용)에서 업무체계 카테고리 트리를 관리합니다.

- **카테고리 관리** — 최상위/하위 추가, 이름변경, 트리 이동, 삭제(최대 5단계, 자기 서브트리 아래로 이동 불가). 삭제는 서브트리에 연결된 맵이 있으면 거부되고, 없으면 서브트리째 삭제됩니다. **맵 배정은 말단(L5)에만** 허용됩니다.
- **카테고리 권한자(Linkage admins)** — 카테고리 행의 권한자 버튼으로 **연계 캔버스 편집 권한자**(사용자/그룹)를 지정합니다. 권한은 **하위 분류로 상속**됩니다 — 상위 레벨(L1~L4)에 지정하면 그 아래 모든 L5 캔버스를 편집할 수 있습니다. 권한자 지정은 sysadmin 전용이고, 카테고리 CRUD·임포트 권한은 그대로 sysadmin에게만 있습니다.
- **연계 캔버스 거버넌스** — L5의 연계 캔버스는 실맵(`mode=framework`)으로 존재하지만 일반 맵 목록·서브프로세스 라이브러리에는 나타나지 않습니다. 카테고리 이름을 바꾸면 캔버스 맵 이름도 함께 바뀌고, **캔버스가 있는 분류(서브트리)는 캔버스를 정리하기 전까지 삭제할 수 없습니다**(409). 권한자의 메이저 확정은 직전 메이저의 마이너 스냅샷을 영구 삭제(프룬)합니다 — 확정 모달이 대상을 미리 보여줍니다.
- **인터뷰 임포트(Interview import)** — 컨설팅사가 전달하는 L5 단위 인터뷰 결과 JSON 파일(여러 개 동시 선택 가능)을 올려 **Dry run**으로 파일별 검증 리포트(오류/경고/알 수 없는 키 경로)와 영향(생성/갱신/변화없음/노트)을 확인한 뒤 **Apply**로 반영합니다. 오류가 있는 파일은 통째로 건너뛰고 나머지만 반영되며, 같은 파일을 다시 실행해도 안전한 멱등 임포트입니다. 업무별 예외 규칙·VOC는 맵의 **Notes** 섹션(맵 상세 카드·에디터 인스펙터)에 표시됩니다. 인터뷰 필드는 고유 필드로 들어옵니다 — 활동의 입력물/산출물/자료 형식/시스템은 노드 필드로, 시작·종료 조건/총시간(분)/실작업시간(분)/시스템은 맵 필드로 착지하고, GMP·빈도·시간 프리텍스트 원문은 **폴백**으로 보존되어 필드 옆 말풍선 아이콘에서 확인·수정합니다. GMP 분류(GMP Direct/Indirect/Non-GMP)와 조건·시간 정리는 **맵 설정 → 상세 → 조건 · GMP** 카드에서 검토·선정하며, 선정한 GMP는 재전달에도 유지됩니다. 미해결 항목(openItems)·업무 메모(tasks note)도 노트로 보존됩니다.

## 14. 설정 레퍼런스

| 변수 | 위치 | 효과 |
| --- | --- | --- |
| `BPM_SYSADMINS` | backend `.env` | sysadmin으로 지정할 로그인 ID 콤마 목록 |
| `AUTH_MODE` | backend `.env` | 인증 모드 — `keycloak` \| `ldap` \| `dev`. 비우면 구 `AUTH_ENABLED`로 유도(`true`→keycloak, `false`→dev). 프론트는 빌드타임 대응값이 없고, 부팅 시 `GET /api/auth/mode`로 런타임 조회한다 |
| `AUTH_ENABLED` | backend `.env` | 구 온/오프 스위치 — `AUTH_MODE`로 대체됨, 하위호환용으로 유지 |
| `AUTH_JWT_SECRET` | backend `.env` | ldap 모드 세션 토큰 서명 키 — **ldap 모드에서 필수**. 교체하면 발급된 모든 로그인 세션이 즉시 무효화됩니다(kill switch) |
| `AUTH_JWT_TTL_HOURS` | backend `.env` | ldap 모드 세션 토큰 수명(시간). 기본 8 |
| `DEV_ENFORCE_PERMISSIONS` | backend `.env` | 인증 없이도 로컬에서 RBAC 강제 |
| `MANUAL_URL` | `.env` (compose) | 에디터 툴바의 매뉴얼 사이트 버튼 — 비우면 숨김 |
| `N8N_HR_URL` | backend `.env` | n8n HR 웹훅 주소(사용자·조직도 단일 소스) — 토큰과 함께 설정해야 동기화 활성 |
| `N8N_HR_TOKEN` | backend `.env` | HR 웹훅 X-API-Key 시크릿 — EDW 직책 웹훅과 공용 |
| `N8N_POSITION_URL` | backend `.env` | EDW 부서장 직책 목록 웹훅 — 비우면 직책 수집 비활성 |
| `HR_SYNC_INTERVAL_HOURS` | backend `.env` | 내장 HR 동기화 스케줄러 주기(시간). 기본 24, 0 = 끔 — 최초 이행 시 0으로 두고 프리뷰·수동 동기화 확인 후 올리세요 |
| `HR_SYNC_DELETE_CAP_PCT` | backend `.env` | 전체 동기화 삭제 상한(관리 행의 %). 기본 20, 0 = 가드 끔 |
| `AI_BASE_URL` | backend `.env` | AI 서버 주소(OpenAI 호환). 현재 사내 GPU는 `https://gpu02.sbiologics.com/v1` |
| `AI_MODEL` | backend `.env` | 기본 모델 id — SGLang 전환 후 **`glm-5.2` 하나**(구 `-think`/`-high`/`-nothink` alias 폐기) |
| `AI_MAX_TOKENS` | backend `.env` | 응답 토큰 상한(사고 토큰 포함). 기본 8000 — **너무 작으면 답이 빈 문자열로 돌아옵니다** |
| `AI_TIMEOUT_SECONDS` | backend `.env` | 호출 1회 타임아웃(초). 최대 사고 모드는 오래 걸려 120~180 권장 |
| `BACKUP_DIR` | `.env` (compose) | db-backup 사이드카의 덤프 저장 경로(호스트). 기본 `./backups` — NAS 마운트로 바꾸면 오프서버 사본이 됩니다 |
| `BACKUP_RETENTION_DAYS` | `.env` (compose) | 백업 보존 일수. 기본 14 |

- 환경변수 변경은 백엔드 재기동이 필요합니다(`--reload`는 `.env`를 다시 읽지 않습니다).
- Keycloak 주소 등 배포별 값은 전부 `.env`로 관리합니다 — 하드코딩 금지.
- 노출 직책(Exposed positions) 목록은 env가 아니라 **설정 → 조직 → 임직원**의 카드에서 저장합니다(7장).
