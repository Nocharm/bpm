# BPM 구현 현황 및 컨설팅 산출물 유지보수 방안 검토

작성 2026-09-28 · 대상: PI팀 협의(의사결정자용)

> 수치·인용은 저장소 기록 기준(2026-09-24 커밋). 기술 근거는 부록에 별도 정리. 계약 범위 및 PI팀 내부 검토 사항은 본 문서에 미반영.

---

## 1. 검토 배경 및 논점

- **당초 합의(2026-08-09 PwC 공유)**: PwC 인터뷰 산출물을 BPM에 일괄 적재하고, 적재 이후의 수정·승인·게시는 현업이 BPM 안에서 수행. 재전달은 변경분만 새 버전으로 반영.
- **현재 상황**: PwC가 Discovery Agent(인터뷰 에이전트)로 인터뷰 및 맵 작성·승인을 수행 중이며, 후속 Redesign Agent(재설계 에이전트)로 이후 수정·개선까지 이어가는 방향을 제시. 이 경우 BPM은 열람 용도로 한정됨.
- **논점**: 컨설팅 계약 종료 이후 프로세스맵의 원본 소재와 유지보수 주체를 어떻게 정할 것인가. 동일 데이터를 두 시스템에서 각각 수정하면 중복 작업과 불일치가 발생하므로, 원본은 한 곳으로 정해야 함.
- **본 문서의 목적**: BPM 구현 현황, PwC 산출물 연계 현황, 유지보수 방안별 장단점을 정리해 PI팀의 이후 운영 방안 결정을 지원.

## 3. PwC 산출물 연계 현황

- **적재 경로**: Discovery Agent 산출물(인터뷰 결과 파일)을 BPM이 읽어 맵을 생성하고 오너·결재자·부서·공개 범위를 설정한 뒤 초판을 게시. 재전달 시 변경된 업무만 새 버전으로 반영하며, 반영 전 사전 검증 보고서로 변경 내역 확인 가능. 이 경로는 구현·검증 완료.
- **진행 상태**: Discovery Agent 인터뷰는 대분류(5단계) 단위로 진행 중. **대분류 간 업무 연결(유관부서 업무)은 미작업 상태이며 이후 계획 미정.** BPM에는 해당 연결의 표현 방식(다른 대분류 업무 참조, 미등록 업무는 자리표시자 후 자동 연결)이 구현되어 있고 PwC에 제안된 상태.
- **8/9 요청 후 미결 사항**: 산출물 형식 초안 공유 시점, 인원 식별 기준(사번·이메일·계정), 전달 주기 및 검토 사이클.
- **Redesign Agent**: 후속 재설계 단계의 산출물 형식과 BPM 반영 방식은 미협의.

## 4. 유지보수 방안 비교

| 구분 | **A. Agent 원본 유지, BPM 열람 전용** | **B. 계약 중 병행, 종료 시 BPM으로 이양** | **C. Agent 소스코드 이관 후 사내 운영** |
|---|---|---|---|
| 계약 기간 중 수정 | Discovery/Redesign Agent에서 수정 후 재전달 | 동일. 병행 기간 BPM 편집은 보류 | 동일 |
| 계약 종료 후 수정 | Agent 접근권·운영 주체에 의존 | 현업 담당자가 BPM에서 수정·결재 | 이관된 Agent를 사내에서 운영 (§5 고려 사항) |
| 담당자 퇴직·조직개편 | Agent 측 반영 여부 확인 필요 | 인사 연동으로 자동 반영 | Agent에 인사 연동 별도 구축 필요 |
| 이력·감사 대응 | Agent 측 이력 기능에 의존 | 버전·결재·코멘트 이력 사내 보존 | 이관 후 확인 필요 |
| 유관부서 업무 연결 | Agent 측 계획 미정 | 구현 완료 | Agent 측 계획 미정 |
| 추가 개발·비용 | 없음 | 없음 | 환경 구축·검토·운영 인력 필요 |
| 계약 종료 후 사내 보유물 | 열람용 데이터 | 데이터·시스템·문서·자동 테스트 | 데이터·이관 코드 (문서·테스트 범위 확인 필요) |

**검토 의견**: 계약 종료 이후의 운영 연속성(수정 경로·인사 변화 반영·이력)은 B안이 안정적. A안은 PwC의 계약 종료 후 지원 범위가 확정되어야 성립하고, C안은 §5의 검토 항목을 통과해야 성립. 최종 선택은 PI팀의 유지보수 계획과 계약 조건에 따라 결정 필요.

## 5. 소스코드 이관 시 고려 사항 (C안)

PwC가 Agent 소스코드 이관 의사를 밝힌 것으로 파악됨. 소스코드 수령과 사내 운영은 별개 사안이며 다음 항목의 사전 확인 필요.

- **실행 환경**: Agent는 PwC 측 서버·데이터베이스·인증 기반에서 동작. 사내 로그인·인사 데이터·백업 체계와 미연결 상태이므로 이관 시 환경 구축을 처음부터 수행해야 함.
- **인수 범위**: 소스코드 외에 설계 문서·운영 설명서·자동 테스트가 함께 제공되는지 확인 필요. 이들 없이 코드만 수령할 경우 이해·수정에 상당한 기간 소요.
- **검토 항목**: 라이선스, 제3자 구성요소, 보안 취약점, 개인정보 처리 방식에 대한 사내 기준 검토 필요.
- **운영 인력**: 이관 코드를 이해하는 인력이 사내에 없음. 이관 후에는 BPM과 Agent 두 시스템을 동일 인력이 유지보수하게 됨.
- **데이터 정합성**: 두 시스템이 동일 데이터를 각각 보유하게 되어 원본 판정 기준을 별도로 정해야 함.

## 6. 계약 종료 이후 운영 상황별 처리

| 상황 | BPM이 원본인 경우 | Agent가 원본인 경우 |
|---|---|---|
| 담당자 퇴직·조직개편 | 자동 감지 → 오너 알림 → 관리자 일괄 교체 | Agent 측 처리 방식 확인 필요 |
| 업무 절차 변경 | 담당자 초안 → 결재 → 게시, 이전 버전과 비교 | Agent 수정 후 재전달 (종료 후 지원 범위에 따름) |
| 신규 업무 추가 | 맵 생성 후 체계 배치(승인) | 동일 |
| 업무 폐지·통합 | 승인 절차로 배치 정리, 연결 자동 갱신 | 동일 |
| 대분류 단위 재정비 | AI 설문 기반 재구성 | 재계약 또는 Redesign Agent 지원 범위 확인 |
| 감사·심사 시 이력 요구 | 버전·결재·코멘트 이력 출력 | Agent 측 이력 기능 확인 필요 |
| 데이터 유실 | 일간 자동 백업 14일 보관, 휴지통 복구 | Agent 측 백업 정책 확인 필요 |

## 7. 협의·결정 필요 사항

1. **원본 소재 및 이양 시점**: 계약 종료 시점에 BPM으로 이양할 것인지, Agent를 계속 원본으로 둘 것인지. 후자의 경우 종료 후 접근권·운영 주체·데이터 반출 조건.
2. **병행 기간 규칙**: 재전달 주기, 재전달 사이 BPM 편집 허용 여부, 충돌 시 우선순위.
3. **전달 형식**: 현재 합의된 인터뷰 파일 형식으로 고정할지. 8/9 미결 3건(형식 초안 시점·인원 식별 기준·전달 주기) 확정.
4. **오너·결재자 명단**: 업무별 인터뷰이=오너, 결재자 계정을 산출물에 포함할지.
5. **Redesign Agent 범위**: 인터뷰 산출물 보정에 한정되는지, 운영 중 프로세스 개선까지 포함하는지. 후자라면 결재·이력·권한·인사 변화 반영 기능 보유 여부와 계약 종료 후 운영 주체.
6. **유관부서 업무 연결 계획**: 수행 주체·시점·방식. BPM 구현분 활용 여부.
7. **소스코드 이관(C안) 검토 여부**: 검토한다면 §5 항목의 사전 확인 일정.

## 8. 보고 순서 (5분)

5. 계약 종료 이후 상황별 처리와 결정 필요 사항 7건. (§6, §7)
