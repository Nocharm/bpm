- **초기 계획 9단계는 전부 완료**, 그 위에 계획에 없던 업무체계(L1~L7)·AI·거버넌스 확장까지 릴리스됨. 착수 2026-06-12, 런칭 2026-07-13, 마지막 릴리스 2026-09-24.

## 3. 컨설턴트 연동 합의 이력 (근거)

2026-08-09 컨설팅사 발송 메일(`docs/notices/2026-08-09-consultant-delivery-interface-mail.md`)과 근거 설계(2026-08-08)에서 합의·공유한 내용:

- **적재는 일괄 자동**: 전달 데이터를 시스템이 적재하고, 맵마다 오너(인터뷰이)·승인자·공개범위를 세팅해 v1 게시까지 완료.
- **적재 이후의 수정·게시는 현업이 시스템 안에서** 기존 절차(편집→승인→게시)로 이어감.
- **재전달은 언제든 가능**: 맵 코드 기준으로 변경된 맵만 새 버전으로 반영. 현업이 수정 중이어도 충돌 없이 이력으로 쌓이고, dry-run 리포트로 상호 확인.
- **역할 분담**: 데이터 작성=컨설턴트 / 검토=임직원+컨설턴트(앱의 트리·비교 화면) / 임포트 실행=관리자 또는 컨설턴트.
- 핵심 원칙 원문: *"임포트는 부트스트랩, 수명주기는 BPM 거버넌스. 컨설턴트 맵 전용 읽기전용 게이트는 두지 않는다."*

즉 "재전달 반복"은 이미 설계에 들어 있어 **계약 기간 중 컨설턴트가 원천을 들고 수정본을 다시 보내는 것 자체는 지원됨**. 문제는 그 상태를 **계약 이후까지 영구화**하고 BPM 편집·승인을 무력화하겠다는 부분.

## 4. 장단점 (솔직한 버전)

### 4-1. BPM을 원천으로 둘 때의 장점

- **소유권이 현업에 있음**: 맵마다 오너·승인자·부서가 박혀 있고, 수정은 담당자가 직접 승인선을 타고 게시. 컨설턴트 없이도 굴러감.
- **이력이 남음**: 버전 append-only, 단계별 코멘트, 누가 언제 무엇을 바꿨는지 비교 화면으로 확인. 감사 대응 가능.
- **조직 변화에 따라감**: HR 동기화로 퇴직·조직개편이 반영되고, 낡은 부서·담당자 참조는 자동 탐지·일괄 교체. 외부 도구는 사내 인사 데이터를 못 봄.
- **체계 무결성 게이트**: L5 확정 게이트 6종(미배치·플레이스홀더·끊긴 링크·미게시·출구 없는 순환·디시전 없는 분기)이 데이터 품질을 강제.
- **AI 보조가 사내 데이터 위에서 동작**: 비교 요약·제출 코멘트 초안·L5 캠페인은 BPM DB를 문맥으로 씀.
- **비용**: 사내 개발·운영이라 추가 라이선스 없음. 컨설턴트 도구는 계약 종료 후 접근권·유지비가 별도 쟁점.

### 4-2. 한계·약점 (저쪽이 짚을 만한 것)

- **인터뷰 수집 도구가 아님**: 현장 인터뷰 진행·정리 워크플로는 컨설턴트 도구가 더 편할 수 있음. BPM은 그 결과를 받는 쪽으로 설계됨(AI 인터뷰 기능은 있으나 컨설턴트 방법론 대체는 아님).
- **양방향 동기화 없음**: BPM→컨설턴트 도구로의 역방향 내보내기는 CSV·Excel·Word 수준. BPM에서 고친 내용이 저쪽 원천에 자동 반영되지 않음. 두 곳을 다 살리면 중복은 구조적으로 발생.
- **실파일 검증 이력이 얕음**: 임포트는 합성 샘플·손타이핑 스키마 기준으로 만들었고, 실전달물 dry-run은 2~3회 수준. 대량 실데이터에서 매핑 이슈가 나올 수 있음(dry-run 리포트가 흡수하도록 설계).
- **단일 개발 라인**: 유지보수 인력이 사내 소수. 기능 요청 대응 속도는 좋았으나 조직 관점 리스크로 보일 수 있음.
- **거버넌스가 무겁게 느껴질 수 있음**: 승인·확정·슬롯 승인이 많아 "빨리 고치고 싶은" 컨설턴트 입장에서는 마찰. 다만 sysadmin·직속 관리자는 즉시 적용 경로가 있음.

## 5. 계약 이후 관리 (컨설턴트가 빠진 뒤)

이 항목이 원천을 BPM에 둬야 하는 가장 강한 이유. 컨설턴트 도구에 원천이 남으면 아래가 전부 사라짐.

| 상황 | BPM에서 처리되는 방식 |
|---|---|
| 담당자 퇴직·조직개편 | HR 웹훅 동기화 → Stale refs 배지 → 오너에게 수정 요청 알림 → 관리자 12곳 일괄 교체 |
| 업무 절차 변경 | 오너가 초안 생성 → 승인선 결재 → 게시, 이전 버전 자동 만료·비교 가능 |
| 신규 업무 추가 | 일반 맵 생성 후 L5 슬롯 연결(승인), 임포트 불필요 |
| L6 폐기·대체 | 슬롯 변경 승인(해제·이양·대체), L5 캔버스 자동 재지정, 계보 이력 |
| L5 단위 재정비 | AI L5 캠페인: 문서 없이 담당자 설문·연결 캔버스로 L6 세트 재구성 → 등록 |
| 전사 조감 | 홈 드릴다운·탐색 다이어그램·현황판(확정 상태·실패 게이트) |
| 결재자 검토 부담 | 비교 AI 요약 보고서 + 제출 코멘트 초안 |
| 데이터 보호 | 일간 자동 백업 14일 보존, 온디맨드 백업, 휴지통 복구 |

컨설턴트 도구가 원천일 때 위 표는 "컨설턴트에게 메일 보내고 재전달 기다림"으로 바뀌고, 계약 종료 후엔 갱신 경로가 없음.

## 6. 운영 방식 시나리오 비교

| | A. 컨설턴트 도구가 원천, BPM은 뷰어 | B. 임포트 후 BPM이 원천(원안) | C. 절충: 계약 중 병행, 종료 시 이양 |
|---|---|---|---|
| 계약 기간 중 수정 | 저쪽 도구에서 수정 → 재전달 | BPM에서 현업이 수정·승인 | 컨설턴트 산출 단계는 저쪽, 확정본은 재전달 → BPM 게시 |
| 중복 업무 | BPM 편집·승인 무의미(현업이 BPM에서 고쳐도 다음 재전달에 덮이거나 이력만 늘어남) | 없음 | 재전달 기간 동안만 BPM 편집 보류(읽기 전용 권장) |
| 계약 종료 후 | 갱신 경로 없음, 원천 접근권 불확실 | 그대로 운영 | 마지막 재전달로 v1~vN 확정, 이후 B와 동일 |
| 인사·조직 변화 반영 | 불가 | 자동 | 이양 후 자동 |
| 필요한 추가 개발 | 없음(현 기능으로 뷰어 가능) | 없음 | 없음. 재전달·dry-run·체크 교체가 이미 있음 |

**추천은 C.** 컨설턴트가 인터뷰·정리를 하는 동안 원천을 들고 있는 건 합리적이고 이미 지원됨. 단, (1) 계약 종료 시점에 마지막 재전달로 이양을 명문화하고, (2) 병행 기간 중 BPM 편집은 보류(또는 오너 편집 시 컨설턴트에게 dry-run 리포트로 통보)해 중복을 없앤다.

## 7. 회의에서 확인·결정할 것

1. **원천 이양 시점**: 계약 종료 시 마지막 재전달로 BPM이 원천이 되는 데 합의하는가. 종료 후 컨설턴트 도구 접근권·데이터 반출 조건은.
2. **병행 기간 규칙**: 재전달 주기(전체/부분), 재전달 사이 BPM 편집 허용 여부, 충돌 시 우선순위.
3. **재전달 포맷 확정**: 인터뷰 JSON 0.5 계약(`docs/samples/interview-json-0.5.md`)으로 고정하는지, 저쪽 실스키마 변환을 누가 맡는지. 8/9 메일의 협의 요청 3건(스키마 초안 시점·인원 식별 기준·전달 주기)이 아직 열려 있음.
4. **오너·승인자 명단**: 맵마다 인터뷰이=오너, 결재자 계정 ID를 산출물에 포함하는지(현재 계약에 있으나 실데이터 확인 필요).
5. **PI팀의 개선 작업 범위**: "그 이후 수정·개선도 저쪽에서"가 인터뷰 산출물 보정을 뜻하는지, 운영 중 프로세스 개선까지 뜻하는지. 후자는 계약 범위·기간 문제.
