# BPM 구현 현황 및 컨설팅 산출물 유지보수 방안 검토

작성 2026-09-28 · 대상: PI팀 협의(의사결정자용)

> 수치·인용은 저장소 기록 기준(2026-09-24 커밋). 기술 근거는 부록에 별도 정리. 계약 범위 및 PI팀 내부 검토 사항은 본 문서에 미반영.

## 1. 검토 배경 및 논점

- **당초 합의(2026-08-09 PwC 공유)**: PwC 인터뷰 산출물을 BPM에 일괄 적재하고, 적재 이후의 수정·승인·게시는 현업이 BPM 안에서 수행. 재전달은 변경분만 새 버전으로 반영.
- **현재 상황**: PwC가 Discovery Agent(인터뷰 에이전트)로 인터뷰 및 맵 작성·승인을 수행 중이며, 후속 Redesign Agent(재설계 에이전트)로 이후 수정·개선까지 이어가는 방향을 제시. 이 경우 컨설팅 범위 맵의 원본은 Agent에 남고, BPM이 그 맵을 별도로 유지할 이유가 없어짐.
- **논점**: 컨설팅 계약 종료 이후 컨설팅 범위 프로세스맵의 시스템 오너를 누구로 할 것인가. 동일 데이터를 두 시스템에서 각각 수정하면 중복 작업과 불일치가 발생하므로 프로세스맵은 한 서비스에서만 관리해야 하며, 계약 중 병행이나 주기적 재전달은 선택지에서 제외.
- **본 문서의 목적**: BPM 구현 현황, PwC 산출물 연계 현황, 유지보수 방안별 장단점을 정리해 PI팀의 이후 운영 방안 결정을 지원.

### 2-3. BPM의 특성: 직접 편집 중심

- BPM은 인터뷰 도구가 아니라 **현업이 캔버스에서 프로세스맵을 직접 수정하는 도구**. 단계 추가·순서 변경·담당 변경·연결 수정을 화면에서 끌어다 놓는 방식으로 처리하고, 수정본은 결재 절차를 거쳐 게시.
- Discovery/Redesign Agent는 인터뷰를 통해 맵을 생성하는 구조이므로, 운영 중 발생하는 소규모 수정(담당자 교체, 단계 하나 추가, 분기 조건 변경 등)도 인터뷰 또는 에이전트 경유 후 재전달이 필요.
- 운영 단계에서는 대규모 재설계보다 소규모 수정이 대부분이며, 이 유형의 작업은 직접 편집 방식이 소요 시간과 절차 면에서 유리.

## 3. PwC 산출물 연계 현황

- **적재 경로**: Discovery Agent 산출물(인터뷰 결과 파일)을 BPM이 읽어 맵을 생성하고 오너·결재자·부서·공개 범위를 설정한 뒤 초판을 게시. 재전달 시 변경된 업무만 새 버전으로 반영하며, 반영 전 사전 검증 보고서로 변경 내역 확인 가능. 이 경로는 구현·검증 완료.
- **진행 상태**: Discovery Agent 인터뷰는 대분류(5단계) 단위로 진행 중. **대분류 간 업무 연결(유관부서 업무)은 미작업 상태이며 이후 계획 미정.** BPM에는 해당 연결의 표현 방식(다른 대분류 업무 참조, 미등록 업무는 자리표시자 후 자동 연결)이 구현되어 있고 PwC에 제안된 상태.
- **8/9 요청 후 미결 사항**: 산출물 형식 초안 공유 시점, 인원 식별 기준(사번·이메일·계정), 전달 주기 및 검토 사이클.
- **Redesign Agent**: 후속 재설계 단계의 산출물 형식과 BPM 반영 방식은 미협의.

## 4. 운영 방안 비교

프로세스맵은 한 서비스에서만 관리하는 것을 전제로 한다. 두 시스템 병행과 주기적 재전달은 중복 작업·불일치·형식 협의 비용만 남기므로 제외한다. 남는 선택지는 계약 종료 후 **컨설팅 범위 맵의 시스템 오너가 PI팀(Agent 존속)인가, BPM인가**로 갈린다.

| 구분 | **안 1. Agent 존속, PI팀이 시스템 오너** | **안 2. 종료 시 1회 이양, BPM이 원본** |
|---|---|---|
| 계약 기간 중 | Agent에서 작성·수정. BPM과 데이터 다리 없음 | 동일. BPM은 관여하지 않음(연동·병행 없음) |
| 계약 종료 시 | 산출물은 Agent에 남고 PI팀이 운영을 인수 | PwC가 완성본을 1회 전달, BPM이 초판으로 게시 |
| 종료 후 수정 | Agent에서 PI팀 주관으로(인터뷰 또는 에이전트 경유) | 현업이 BPM 캔버스에서 직접 수정 → 결재 → 게시 |
| 담당자 퇴직·조직개편 | Agent 측 반영 방식 확인 필요 | 인사 연동으로 자동 반영 |
| 이력·감사 | Agent 측 이력 기능에 의존 | 전달 이후 이력은 BPM에 보존. 계약 중 이력은 완성본 전달에 포함되지 않음(시점별 파일을 순서대로 적재하면 버전으로 남길 수 있음) |
| 유관부서 업무 연결 | Agent 측 계획 미정 | BPM 구현분 사용 |
| BPM 서비스 | 컨설팅 범위 맵을 담지 않으므로 운영 범위 재정의: 서비스 종료 또는 업데이트 중지(동결). 사내 자체 작성분의 처리(읽기 전용 보존 또는 내보내기 후 종료) 별도 결정 | 계속 운영 |
| 추가 비용·인력 | Agent 운영 인력·인프라·라이선스(§5) | 없음. 이양은 기존 가져오기 경로로 1회 처리 |
| 성립 조건 | §5 항목을 PI팀이 확보 | 계약에 "종료 시 최종 산출물 1회 전달" 조항, 전달 형식과 식별 키 규칙(§6) 고정 |

**검토 의견**: 두 안 모두 성립하며 차이는 오너 결정 하나. 안 1은 BPM 운영 종료·동결 결정이 따라오므로 §2의 구현분과 사내 자체 작성 데이터의 처리를 같이 정해야 한다. 안 2는 추가 개발 없이 성립하지만 전달 형식과 식별 키가 계약 종료 전에 고정되어야 한다.

## 5. 안 1 채택 시 PI팀이 확보할 항목 (Agent 운영)

Agent를 사내에서 계속 운영하려면 시스템 오너로서 다음이 확보되어야 한다. 소스코드 이관은 이 항목들의 한 수단이며, 이관 자체가 운영을 보장하지는 않는다.

- **운영 주체와 인력**: Agent를 이해하고 수정할 인력. 현재 사내에 없음. 이관 후에는 BPM과 별도로 PI팀이 유지보수 주체가 됨.
- **실행 환경**: Agent는 이미 사내 인프라에 배포되어 있고 사내 로그인 연동도 되어 있는 것으로 파악됨(확인 필요). 인사 데이터 연동·백업 체계·모니터링이 사내 운영 기준에 맞는지 확인 대상.
- **인수 범위**: 소스코드 외에 설계 문서·운영 설명서·자동 테스트가 함께 제공되는지 확인. 이들 없이 코드만 수령할 경우 이해·수정에 상당한 기간 소요.
- **검토 항목**: 라이선스, 제3자 구성요소, 보안 취약점, 개인정보 처리 방식에 대한 사내 기준 검토.
- **종료 후 지원**: 계약 종료 후 PwC의 지원 범위(장애 대응·업데이트) 확정.

## 6. 안 2 채택 시 전달 조건: 식별 키

BPM의 변경 비교와 새 버전 반영은 전달 파일의 식별 키에 의존한다. 완성본 1회 전달이면 아래 중 맵 식별과 인원 식별만 맞으면 되고, 계약 중 시점별 파일까지 적재해 비교하려면 단계 식별 규칙까지 합의가 필요하다.

- **맵 식별**: 파일의 `taskId`(6단계 업무 코드). 전달 간 같은 코드여야 같은 맵의 새 버전으로 반영되고, 코드가 바뀌면 신규 맵이 생기고 기존 맵이 남는다.
- **단계 식별**: 현재 형식은 단계에 별도 id가 없고 순번(seq)으로 식별한다. 중간 단계 삽입으로 순번이 밀리면 이후 단계가 전부 "삭제+추가"로 비교되어 변경 비교의 의미가 줄어든다. 시점별 적재를 원하면 순번 유지 또는 단계 id 도입을 PwC와 합의해야 한다.
- **인원 식별**: 사번·이메일·계정 중 무엇으로 오너·결재자를 지정할지(8/9 미결).
- **유관부서 참조**: 대분류 간 연결이 미작업이라 완성본에 없으면 BPM에서 사람이 연결한다.

| 상황 | 안 2(BPM 원본) | 안 1(Agent 원본, PI팀) |

| 데이터 유실 | 일간 자동 백업 14일 보관, 휴지통 복구 | Agent 측 백업 정책 확인 필요 |

## 8. 협의·결정 필요 사항

1. **컨설팅 범위 맵의 종료 후 시스템 오너**: PI팀(Agent 존속) 또는 BPM(종료 시 1회 이양). 이 결정이 나머지 항목을 정한다.
2. **안 1이면**: Agent 운영 조건(§5)의 확보 계획과 시점, BPM 운영 범위(종료 또는 동결)와 사내 자체 작성분 처리 방침.
3. **안 2이면**: 계약에 "종료 시 최종 산출물 1회 전달" 조항, 전달 형식(현재 합의된 인터뷰 파일 형식) 고정, 식별 키 규칙(§6), 인원 식별 기준, 오너·결재자 명단 포함 여부.
4. **Redesign Agent 범위**: 인터뷰 산출물 보정에 한정되는지, 운영 중 프로세스 개선까지 포함하는지. 후자라면 결재·이력·권한·인사 변화 반영 기능 보유 여부.
5. **유관부서 업무 연결 계획**: 수행 주체·시점·방식. 안 2이면 BPM 구현분 활용 여부.

## 9. 보고 순서 (5분)

1. 논점: 프로세스맵은 한 서비스에서만 관리. 계약 종료 후 컨설팅 범위 맵의 시스템 오너. (§1)
2. BPM 현황: 초기 계획 완료, 직접 편집 중심 도구, 컨설팅 대응 항목 대부분 구현 완료. (§2)
3. PwC 연계 현황: 적재 경로 완료, 유관부서 연결 미작업·계획 미정. (§3)
4. 안 1·안 2 비교와 각 안의 성립 조건. (§4, §5, §6)
5. 계약 종료 이후 상황별 처리와 결정 필요 사항 5건. (§7, §8)
