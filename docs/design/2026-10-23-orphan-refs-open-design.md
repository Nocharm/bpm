# 고아 참조 정리 — 일반 사용자 오픈 설계 (v1.3.1)

> 상태: 구현 완료(dev). 시안: claude.ai 아티팩트 "고아 참조 시안" 3차 + 2026-10-23 피드백.
> 선행: 고아 참조 감사 트랙(`backend/app/ref_audit.py`, 2026-09-09, sysadmin 전용).

## 1. 의도

조직 개편과 퇴직으로 사라진 부서·사람의 이름이 맵 설정, 노드, 그룹, 카테고리 권한에 남는다. 지금은 sysadmin만 설정 › 조직 › Orphaned refs에서 일괄로 고칠 수 있고, 일반 사용자는 홈 카드 배지와 캔버스 ⚠로 "있다"는 것만 본다. 이 기능은 **각자 평소에 고칠 수 있는 범위 안에서** 같은 일괄 정리를 일반 사용자에게 연다. 화면은 처음 보는 사람도 한눈에 이해하도록 그림 설명과 카드 그리드로 다시 만든다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 일반 사용자가 자기 범위의 고아 참조를 찾아 대체·제거하거나, 못 고치는 줄은 고칠 사람에게 알린다.
- 같은 줄은 누가(sysadmin 포함) 고쳐도 평소 화면과 같은 결과가 난다(공통 규칙).
- 내가 직접 고칠 곳이 있으면 빨간 점이 상단 바 → 메뉴 → 설정 탭으로 길을 안내한다.

**비목표**
- 고아 참조의 자동 정리(배치)나 HR 동기화 시점 자동 치환.
- 끝 제목 고아(하위프로세스 출구 끝 키) 스캔 — 기존 한계 유지.
- 새 승인 종류 신설. 기존 `permission_downgrade` 등 평소 흐름만 탄다.

**반목표(이렇게 되면 실패)**
- 감사 화면이 평소 규칙을 우회하는 옆문이 되는 것(결재 중 승인자 변경, 승인 없는 Editor 제거, 남의 점유 강탈).
- 게시본이 직접 바뀌는 것.
- 사용자가 결과를 예측하지 못하는 것 — 누르기 전에 줄마다 결과와 알림 수신자가 보여야 한다.

## 4. 범위 — 누가 어떤 줄을 보나

뷰어(actor)가 볼 수 있는 줄은 아래 합집합이다. 나머지 줄은 응답에서 뺀다.
- 맵 줄(설정·노드): `effective_role(actor, map)` ∈ {editor, owner}. sysadmin은 모든 맵에서 owner. 오우닝 부서 소속 파생 editor 포함. 소프트삭제 맵의 오우닝 줄은 sysadmin만(현행 유지).
- 그룹 멤버 줄: actor가 그 그룹의 관리자이거나 sysadmin.
- 카테고리 권한 줄: `_assert_can_manage_appointments`를 통과하는 카테고리(sysadmin 또는 상위 위임 관리자).

## 5. 줄별 결과 판정 (공통 규칙)

판정은 서버가 actor 기준으로 줄마다 하나를 정해 응답에 싣고, 적용 시점에 다시 판정한다(그 사이 상태가 바뀌면 적용 시점 판정이 이긴다).

| 결과 | 뜻 | 화면 칩 |
|------|----|--------|
| `direct` | 그 자리에서 바뀜 | 바로 반영 |
| `checkout` | 점유 없는 작업본을 actor가 점유하고 고침 | 점유하고 반영 |
| `new_draft` | 게시본만 있어 새 Draft를 만들어 고침 | 새 Draft · 게시 필요 |
| `approval` | 평소처럼 승인 요청이 올라감 | 승인 요청 |
| `notify` | 고칠 권한·점유가 없어 고칠 사람에게 알림 (`notify_to` 동반) | 점유자에게 알림 / 오너에게 알림 |
| `locked` | 지금은 아무도 이 경로로 못 고침 (`reason` 동반) | 잠김 |
| `pending` | 작업본에는 이미 고쳐져 있고 게시본에만 남음 | 게시 대기 |

소스별 규칙(R = actor의 맵 역할, sysadmin은 owner):

| 소스 | 고칠 수 있는 사람 | 판정 |
|------|------------------|------|
| `map_collab`·`map_grant` (사람·부서 grant) | Editor 이상 | viewer grant → `direct`. editor grant → R=owner면 `direct`, 아니면 `approval`(옛 grant 제거를 `permission_downgrade` 요청으로, 대체면 새 grant는 즉시 추가). 퇴직자가 작업본 점유·결재 제출자면 `locked`(reason `in_workflow`). 같은 grant에 대기 중 요청이 있으면 `locked`(reason `request_pending`). |
| `map_owner` | Owner(퇴직 오너 맵은 사실상 sysadmin) | R=owner → `direct`(대체만), 아니면 `locked`(reason `owner_left`). 새 오너는 평소 오너 이전 후보 규칙(`lib/owner-candidates.ts` ↔ `transfer_owner`: 명시 editor 이상 ∪ 주관 부서 소속)을 따른다. 후보가 아니면 그 줄만 `locked`(reason `not_eligible`). 퇴직한 옛 오너의 grant는 지운다(평소 이전은 옛 오너를 editor로 남기지만 퇴직자라 새 고아만 생긴다 — 의도한 차이). |
| `map_approver` | Owner | PENDING·APPROVED 버전이 있으면 누구든 `locked`(reason `in_approval`). R=owner → `direct`. R=editor → `notify`(오너). |
| `owning_dept` | Owner | R=owner → `direct`(대체만). R=editor → `notify`(오너). |
| `sp_dept`·`sp_assignee` | Owner | R=owner → `direct`(부서는 대체만). R=editor → `notify`(오너). |
| `node_dept`·`node_assignee` | Editor 이상 | §6 버전 규칙. |
| `group_member`·`group_user` | 그룹 관리자·sysadmin | `direct`. |
| `category_perm` | 임명 관리자·sysadmin | `direct`. |
| 업무 체계 캔버스(`mode=framework`)의 모든 줄 | — | `locked`(reason `framework`) — 확정 흐름 전용, 평소에도 협업자·승인자 API가 422. |

- 제거 금지(현행 `REMOVE_BLOCKED`): 오너·주관 부서·SP 부서. 부서 카드는 제거 모드 자체가 없다(현행 유지).
- `notify` 수신자가 없으면(오너 퇴직 등) `locked`(reason `owner_left`). 수신자가 actor 자신이어도(오너 미지정 맵의 생성자 등) 고칠 다른 사람이 없으니 같은 잠김.
- `approval`인데 그 맵에 재직 중인 승인자가 없으면 요청이 영영 대기에 남는다 → 대신 `notify`(오너, 오너는 바로 고칠 수 있다). 오너도 없으면 `locked`(reason `owner_left`).
- 결과 중 일부는 고른 대체 값에 따라 달라진다(오너 후보 여부). 그래서 GET은 값 없이 판정하고, 상세 창에서 대상을 고르거나 모드를 바꾸면 미리보기 API로 줄 판정을 다시 받는다(§8).
- 경고(`no_access`·`no_new_grant`)는 직접 고치는 결과(`direct`·`checkout`·`new_draft`·`approval`)의 줄에만 붙인다. 알림·잠김·게시 대기 줄은 아무것도 쓰지 않으니 경고할 대상이 없다.
- 노드 담당자 대체 값의 맵 열람권은 평소에도 서버가 강제하지 않는다(피커만 거름) → 강제하지 않되, 미리보기가 그 맵을 못 보는 사람이면 줄에 경고(`warning: "no_access"`)를 싣는다. 적용하면 캔버스에 "열람권 없음" 경고가 생기기 때문이다.
- 공개 맵의 viewer grant 대체: 평소 규칙상 공개 맵엔 viewer를 줄 수 없으니 대체는 "제거만" 일어난다(새 grant 추가 생략, 응답에 표시). 대체 대상이 오우닝 부서와 같으면 마찬가지로 추가 생략.

## 6. 노드 줄 — 어느 버전에 쓰나

노드 줄은 버전이 아니라 **맵 단위 한 줄**로 낸다(`target_id = node_dept:{map_id}` 등). W = 그 맵의 최신 버전이 게시본이 아니면 그 버전(작업본: DRAFT·REJECTED·PENDING·APPROVED), 게시본이면 없음.

| 상황 | 판정 |
|------|------|
| W 없음(최신=게시본, 게시본에 값 있음) | `new_draft` — 게시본을 복제한 새 버전(라벨 `Reference cleanup`, 점유=actor, `created` 이벤트)에 고친다. |
| W가 DRAFT·REJECTED, 점유=actor | `direct` (Q2 a) |
| W가 DRAFT·REJECTED, 점유 없음 | `checkout` — 점유를 가져오고 고친다 (Q2 b). actor에게 대기 중 권한 다운그레이드 요청이 있으면 `locked`(reason `request_pending`, acquire_checkout과 같은 가드). |
| W가 DRAFT·REJECTED, 다른 사람 점유 | `notify`(점유자) (Q2 b) |
| W가 PENDING·APPROVED | `locked`(reason `in_approval`) |
| 게시본엔 값이 있고 W에는 없음 | `pending` — 고칠 것 없음, 게시 대기 카드. |

- 곳 수(count)는 고칠 대상 버전(W, 없으면 게시본)의 노드 수. W와 게시본에 모두 있으면 W 기준 한 줄.
- 노드에 쓰는 값: 부서는 리프명, 담당자는 직원 표시명(현행 `_resolve_to_value`). 담당자 목록에서 해당 이름만 바꾸거나 빼고 중복은 합친다.
- 쓴 버전은 `updated_at`을 올린다.
- 현행 스캔(`load_target_versions`)이 APPROVED 작업본을 빼던 빈틈도 이 규칙으로 메운다.

## 7. 알림

- `notify` 줄은 적용 버튼 하나로 함께 처리된다: 수신자별로 묶어 1건씩(기존 `ref_fix_requested` 유형 재사용, payload에 맵 목록·소스별 개수·`as: "owner"|"holder"`(줄 응답의 `notify_to.role`과 같은 값)).
- 상세 창의 알림 줄에는 수신자 이름을 그대로 보인다("오너에게 알림 · <표시명>" 형태).
- 승인 요청(`approval`)은 평소 `permission_downgrade` 경로의 알림을 그대로 탄다.

## 8. API

기존 `/api/admin/ref-audit*`(sysadmin 게이트) 3개를 아래로 대체한다(관리 전용 화면이 없어지므로 제거).

- `GET /api/ref-audit` — actor 범위의 카드 목록.
  - `departments[]`, `users[]`: 카드 = 같은 대상의 묶음. 부서는 리프명으로(경로 그룹과 리프 그룹을 합침), 사람은 표시명으로(로그인 그룹은 비활성 직원 기록으로 이름을 찾아 이름 그룹과 합침, 못 찾으면 로그인 그대로).
  - 카드: `key`, `label`, `sub`(부서는 상위 경로, 사람은 로그인 또는 없음), `lines[]`.
  - 줄: `target_id`, `from_value`, `source`, `count`, `outcome`, `reason?`, `notify_to?{id,name,role}`, `map_id?`·`map_name?`·`map_role?`·`version_label?`, `group_id?`·`group_name?`, `category_id?`·`category_name?`.
  - `scope`: `{maps: n, groups: n, categories: n}`(히어로 "범위" 칩).
- `GET /api/ref-audit/summary` — `{actionable: n}` = outcome이 `direct`·`checkout`·`new_draft`·`approval`인 줄의 곳 수 합. 빨간 점 소스.
- `POST /api/ref-audit/preview` — apply와 같은 본문으로 줄별 `outcome`·`reason`·`notify_to`·`warning`만 돌려준다(쓰기 없음). 상세 창의 줄 칩과 "적용하면" 요약이 이 응답을 쓴다.
- `POST /api/ref-audit/apply` — `{kind, mode: replace|remove, to_value?, targets: [{target_id, from_value}]}`.
  - 한 트랜잭션: 범위 안 대상 맵 잠금 → 다시 판정 → 결과별 적용 → 알림 생성 → commit. 검증 실패(대상 아님·제거 금지·대체값 무효)는 422 전체 거부(현행과 같음). 맵 잠금은 점유·제출과 줄 서지 않으므로 노드 줄은 쓰기 직전에 작업본 행을 잠가 판정 때 상태(편집 가능, direct=내 점유·checkout=점유 없음)인지 다시 보고, 아니면 쓰지 않고 이미 바뀜으로 건너뛴다.
  - 응답: 결과별 곳 수, 만든 Draft 목록(맵·버전 id), 승인 요청 수, 알림 수신자 수, 건너뛴 줄(이미 바뀜·범위 밖. 없는 대상도 범위 밖으로 답한다).

## 9. 화면

**진입·빨간 점**
- 상단 바 사용자 이름 버튼에 빨간 점(`summary.actionable > 0`). 메뉴를 열면 점은 "설정" 줄로 옮겨 보이고, 설정에서는 "고아 참조" 탭 옆에 보인다.
- 설정의 새 분류 "점검"(en "Checks", 가칭)에 "고아 참조" 탭. 접근 `everyone`. sysadmin도 이 탭 하나를 쓴다(조직 분류의 기존 탭 제거).
- 요약은 상단 바·설정 레일이 공유하는 구독 하나로 받고(요청 1번), 적용 직후 다시 받는다(창 이벤트). 범위가 빈 사용자는 서버가 스캔 없이 0을 돌려준다.

**페이지**(시안 3차 기준)
- 위쪽 약 1/3: 히어로 — 제목·한 줄 설명·숫자 3개(부서·사용자·고칠 곳)·범위 칩·다시 스캔, 오른쪽 SVG 그림(오늘의 조직도 ↔ 맵, 끊긴 고리). 그림 위 **경우별 호버 아이콘 8개**(오너·승인자·협업자/권한·주관 부서·노드·SP 지정·그룹·카테고리) — 설명창은 "어디 / 누가(역할 칩) / 대체·제거 아이콘 칩 / 주의 한 줄". 결과 칩 범례(호버 한 줄 설명).
- 아래: 부서·사용자 두 섹션, 폭이 되면 2열이며 **부서 열이 더 넓다**(약 1.35:1).
  - 부서 카드: 가로형(약 4:3). 윗변 띠, 각진 타일 + 이름 + 상위 경로, 오른쪽 위 숫자(단위 글자 없음), 가운데 걸린 맵 최대 2줄(3개 이상이면 "외 N개 맵"), 아래 결과 막대 + 고침·알림·잠김·게시 대기 집계.
  - 사용자 카드: 정사각, 가운데 정렬. 아바타(시안보다 작게) 둘레에 결과 비율 링, 이름, 로그인(없으면 "이름만 남음"), 집계. 오른쪽 위 숫자(단위 글자 없음).
  - 카드 크기는 섹션 안에서 같고 줄바꿈(wrap) 그리드. 게시 대기만 남은 카드는 "게시 대기" 표시로 뒤에 정렬.
- 카드 클릭 → 상세 창(공용 `ModalBackdrop`, 유리 dense): 머리(이름·부가정보·맵 수·곳 수) / `[사라진 이름] → [바꿀 대상 피커 | 지우기]` + 대체·제거 아이콘 세그먼트(부서는 제거 비활성) / 맵별 줄 목록(맵 이름은 **맵으로 바로가기 링크**, 그룹은 설정 › 유저 그룹으로) — 줄마다 체크·소스·내용·짧은 메모·결과 칩, 알림 줄은 수신자 이름 / 아래 "적용하면" 결과별 칩 + 취소·적용(제거는 빨간 "지우기").
- 다시 스캔·적용 결과는 토스트로 요약("N곳 반영 · M곳 게시 필요 · K곳 알림").
- UI 문구는 en 기본 + ko, 긴 대시 금지, `data-id` 부여, 아이콘 Lucide 16/1.5.

## 10. 알려진 위험과 대응

- **내 점유 Draft를 다른 탭 에디터로 열어 둔 경우(Q2 a)**: 그래프 PUT에 낙관적 동시성 검사가 없어, 열린 에디터가 다음 자동 저장에서 이 변경을 되돌릴 수 있다. 대응: a 줄 메모와 적용 확인에 "열어 둔 에디터는 새로 고침" 안내. 근본 대책(그래프 PUT 버전 검사)은 별도 트랙.
- **스캔 비용**: 요약 API가 페이지 로드마다 전체 스캔을 돈다. 현 규모에서 허용(쿼리 수 고정, 홈 맵 목록과 같은 급). 느려지면 서버 캐시를 별도로.
- **합친 카드의 잘못된 묶음**: 서로 다른 사라진 경로가 같은 리프명이면 한 카드로 합쳐진다. 적용은 줄별 `from_value`로 하므로 데이터 오염은 없다.
- **홈 배지와 숫자가 다르다(의도)**: 홈 카드 배지(`count_stale_refs_by_map`)는 "그 맵에 남은 낡은 참조"(게시본·작업본 각각)를 세고, 이 화면은 "내가 다룰 줄"(맵 단위 한 줄, 게시 대기 별도)을 센다. 홈 배지는 그대로 두고, 둘 다 APPROVED 작업본을 빼던 빈틈만 고친다. 2026-09-09 설계의 "배지=감사 범위" 불변식 테스트(`test_list_maps_stale_ref_count_matches_audit_scan_scope`)는 새 정의로 고쳐 쓴다.

## 11. 빌더에게 맡기는 것

- 라우터 가드의 판정 조각(결재 진행 여부, 다운그레이드 승인 필요, 워크플로 참여자, 대기 요청)을 라우터와 감사가 함께 쓰도록 공용 헬퍼로 옮길지, 감사 쪽에 판정 모듈을 둘지. 원칙: 같은 판정이 두 벌로 갈라지지 않게.
- SVG 그림의 정확한 배치·애니메이션, 카드 크기 수치, i18n 키 이름, 컴포넌트 분할.
- 홈 경고 모달의 "Draft에서 고치세요" 문구를 새 탭 링크로 바꿀지(작으면 함께).

## 12. 검증

- pytest: 소스 × 역할(viewer·editor·owner·sysadmin) 판정표, 노드 버전 규칙 6가지, 범위 필터(뷰어는 줄 없음), 공통 규칙(sysadmin도 결재 중 승인자 잠김·Editor 제거는 owner일 때만 즉시), 적용이 승인 요청·새 Draft·점유 이전·알림을 만드는지, 422 전체 거부.
- vitest: 카드 집계·정렬·맵 줄 요약·링 비율 순수 함수.
- Playwright: 일반 사용자(Editor)·sysadmin 각각으로 점 경로 → 탭 → 카드 → 상세 창 → 적용 → 점 갱신, 스크린샷 공유.
- 게이트: 백엔드 전체 pytest·ruff, 프론트 tsc·lint·vitest 전체·컴포넌트 카탈로그 재생성.
