# 컨설턴트 전사 프로세스 체계(7단계) 수용 — 설계

> 2026-08-08 브레인스토밍 확정. 컨설팅 업체가 현업 인터뷰로 정립하는 전사 프로세스 7단계를 BPM으로 마이그레이션하고, 이후 유지보수를 BPM 안에서 이어가기 위한 설계. 거버넌스 UX 확장(게시 모달 가시성 동봉·맵 카드 권한 편집·승인 탭 통합)은 별도 트랙 — [`2026-08-08-governance-ux-design.md`](2026-08-08-governance-ux-design.md).

## 1. 배경 · 7단계 → BPM 매핑

| 컨설턴트 개념 | BPM 대응 |
|---|---|
| L1~L5 — 카테고리(상호 독립 분류, 큰 업무) | 신설 `process_categories` 트리 — 조직도(`owning_department`)와 **별개의 분류 축** |
| L6 — 하나의 업무 | 맵 1개 |
| L7 — 단위 업무 | 맵 안의 노드 (파라미터 없음 — 파라미터는 L6에만) |
| 연계업무 — L6↔L6 연결(예외: 특정 지점 부착) | 맵 안의 **subprocess(Call Activity) 노드**로 변환 |
| L6 파라미터 + Input/Output | **SP 지정 확장** — 기존 `sp_*` + 신설 `sp_input`/`sp_output` |
| 전달물 — 컨설턴트 테이블(pg dump 등, 스키마 미정) | **canonical JSON 계약**(§4)으로 변환해 임포트. 실스키마→canonical 어댑터는 스키마 확정 후(§7 Phase 3) |

### 핵심 원칙 — 임포트는 부트스트랩, 수명주기는 BPM 거버넌스

임포트가 맵마다 **오너(인터뷰이)·승인자·오우닝 부서·가시성 세팅 → 게시**까지 수행해 소유권을 현업에 이양한다. 이후 수정·폐기·대체는 컨설턴트 전용 장치 없이 BPM의 기존 거버넌스(드래프트→승인→재게시, 휴지통, 버전 이력)가 담당한다. 컨설턴트 맵 전용 읽기전용 게이트는 **두지 않는다**.

### 역할 분담

| 역할 | 담당 | 수단 |
|---|---|---|
| 데이터 작성 | 컨설턴트 | 외부 테이블 → canonical JSON |
| 검토 | 임플로이 & 컨설턴트 | 앱: 카테고리 트리 열람 + 버전 비교 화면 |
| 임포트 실행 | 관리자 or 컨설턴트 | 서버 스크립트(§5). 컨설턴트 셀프서브가 필요해지면 sysadmin 업로드 UI 후속 |

## 2. 데이터 모델

### 2.1 `process_categories` (신설 테이블)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | PK | |
| `code` | String, unique | 컨설턴트 카테고리 키 — **멱등 업서트 키**(개명 안전) |
| `name` | String | 표시명 |
| `level` | int (1~5) | 계층 깊이 |
| `parent_id` | FK self, nullable | L1은 NULL |
| `sort_order` | int | 형제 간 정렬 |

빈 카테고리(하위 맵 없음)도 행으로 존재 — 트리 뷰에 빈 슬롯으로 표시된다.

### 2.2 `ProcessMap` 컬럼 추가 — 전부 `db.py _ADDED_COLUMNS` 등록 필수(운영 자동 ALTER)

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `category_id` | FK → process_categories, nullable | **체계 소속 판정 = 이 값의 존재.** 모든 레벨 허용 — 리프(L5)엔 L6 업무 맵, 비-리프(L1~L4)엔 오버뷰 맵을 대표로 연결 가능 |
| `consultant_code` | String, unique, nullable | L6 멱등 업서트 키. 임포트된 맵만 non-null(출처 구분 겸용) |
| `sp_input` | Text, nullable | L6 Input — 자유 텍스트(스키마 미정이라 구조화 유보, Text라 후속 리스트 승격 무손실) |
| `sp_output` | Text, nullable | L6 Output — 동상 |

`origin` 같은 출처 태그는 **두지 않는다** — 체계 필터 축은 `category_id`, 출처는 `consultant_code`로 충분. 덕분에 일반 맵도 카테고리만 연결하면 체계에 편입된다(§6 대체·신규 추가).

### 2.3 L6 파라미터 = SP 지정

컨설턴트 L6 파라미터는 기존 SP 지정 필드(`sp_duration`·`sp_cost_krw`/`sp_cost_usd`(배타)·`sp_headcount`·`sp_description` 등)에 매핑하고 Input/Output만 신설한다. 연계를 subprocess 노드로 변환하려면 대상 맵의 SP 지정(게시본 필수)이 어차피 필요하므로, **임포트 맵은 게시 후 전원 자동 SP 지정**된다. `annual_count`·`fte`는 기존 계약대로 부모 맥락 값 — 연계 노드 행에 저장.

## 3. 수명주기 시나리오 (기존 개념으로 해소)

| 시나리오 | 동작 |
|---|---|
| 수정 | 오너(인터뷰이)/부서원이 기존 드래프트→승인→재게시 워크플로로 |
| 폐기 | 기존 휴지통(소프트삭제) + 카테고리 연결 해제 → 트리엔 빈 슬롯 |
| 일반 맵으로 대체 | **슬롯 이양**: `category_id`+`consultant_code`를 새 맵으로 이전(오너/sysadmin 액션, §6) |
| 신규 업무 추가 | 일반 맵에 카테고리 연결만 하면 체계에 편입 — 임포트 불요 |
| 전사 오버뷰 | 전 L6가 SP 지정되므로 **기존 기능으로 그리는 일반 맵**(L6들을 라이브러리에서 끌어다 노드로, 연계를 엣지로). 비-리프 카테고리에 대표로 연결. 자동 생성은 하지 않음(후속 옵션) |

## 4. Canonical 임포트 계약

**1회 전달 = 디렉터리 2파일**: `categories.json`(카테고리 전체) + `maps.jsonl`(**1줄 = 1맵** — 2만 맵 스케일에서 스트리밍 파싱 필수, §8). **어댑터가 컨설턴트 테이블에서 자동 생성**하는 기계 산출물이며 수기 작성 양식이 아니다 — 사람 손은 스키마 매핑 규칙(Phase 3 어댑터) 1회.

```json
// categories.json
{
  "categories": [
    { "code": "A01", "name": "구매", "level": 1, "parent": null }
  ]
}
// maps.jsonl — 한 줄에 맵 하나(아래는 펼쳐 쓴 예시)
{
  "code": "A01-B02-...-L6-01",
  "name": "원자재 구매 요청",
  "category": "<L5 code>",
  "owner": "hong.gildong",
  "approvers": ["kim.cs"],
  "department": "Division/Office/Team",
  "visibility": "public",
  "params": { "duration": "", "cost_krw": "", "cost_usd": "", "headcount": "",
              "annual_count": "", "fte": "", "input": "", "output": "" },
  "nodes": [
    { "code": "N1", "name": "…", "type": "process", "department": "", "assignee": "", "system": "", "seq": 1 }
  ],
  "edges": [ { "from": "N1", "to": "N2", "label": "" } ],
  "links": [ { "to_map": "<L6 code>", "after_node": "N9" } ]
}
```

- `owner`/`approvers`는 login_id. 컨설턴트가 이름으로 주면 어댑터(Phase 3)가 employees로 해석 + 미매칭 리포트.
- `visibility`: `public`(기본) | `private` — 업무 성격에 따라 맵별 선택.
- `params`는 L6 전용(L7 `nodes[]`엔 파라미터 없음). `cost_krw`/`cost_usd` 배타는 기존 계약 그대로.
- `params.annual_count`/`fte`는 부모 맥락 계약(2026-07-13)에 따라 **이 맵을 참조하는 연계 subprocess 노드 행에 시드**된다(맵 컬럼 신설 없음). 아무 데서도 참조되지 않는 L6이면 값이 실릴 곳이 없음 — dry-run 리포트에 기록.
- `params.duration`은 H.MM 계약(`app/duration.py`) — 무효값은 경계에서 **조용히 `""` 소거**되므로 정규화는 어댑터/작성자 책임. dry-run 리포트가 무효 duration을 경고로 잡는다.
- `edges` 생략 시 `seq` 순 체인. `type`은 `process`|`decision`(Start/End는 임포트가 시드).
- `links[]` = 연계업무 → subprocess 노드. `after_node` 생략 시 흐름 끝에 부착("예외" 케이스가 `after_node`로 특정 지점 부착).

## 5. 임포트 스크립트 — `scripts/import_consultant.py`

### 5.1 apply 동작

1. 카테고리 업서트(`code` 기준).
2. **2-pass**: 맵 전체를 먼저 생성/결착(`consultant_code`) → 그다음 그래프 빌드. 연계 대상이 항상 존재하므로 플레이스홀더 불필요.
3. 신규 맵 생성 시: 오너·승인자(MapApprover)·오우닝 부서(§5.3)·가시성·카테고리 연결 세팅.
4. 그래프 빌드: Start/End 시드 + L7 노드 + 엣지 + 연계 subprocess 노드. 좌표는 레이어드 레이아웃(BFS 랭크 → 열 배치)으로 계산.
5. **변경 있는 맵만** 새 버전 적재 + 게시(승인 워크플로 우회 — sysadmin 시스템 부트스트랩 경로). 무변경 맵은 손대지 않음.
6. 게시 후 SP 지정 + L6 파라미터·Input/Output 갱신.

### 5.2 재임포트 정책 — "아무것도 안 막고, 아무것도 안 잃는다"

- `consultant_code`로 기존 맵 결착 → **최신 게시본과 비교** → 변경 시 새 버전 적재+게시. 버전은 append-only 이력이므로 현업 편집도 이력에 보존된다 — 현업이 노드 하나를 옮겨도 재임포트는 **절대 막히지 않는다**(스킵/차단 정책 없음).
- 피드백 루프: 임플로이 검토 → 컨설턴트에 피드백 → 데이터 수정 → 재임포트 → 버전 비교 화면으로 반영 확인 → 반복.
- 변경점 확인 2겹: 적용 전 `--dry-run` 리포트(맵별 노드 추가/삭제/수정·파라미터 변경 요약, CSV 임포트의 변경점 프리뷰와 같은 개념) + 적용 후 기존 **버전 비교 화면**(직전 게시본 vs 임포트본).
- 후속 옵션: `--review`(게시 보류하고 검토 대기 버전으로만 적재) — 기본은 적재+게시(컨설팅 기간에 수십 맵 개별 게시 마찰이 더 큼).
- 슬롯이 대체된 경우(§6): `consultant_code`가 새 맵으로 이전돼 있으므로 재임포트는 새 맵에 결착된다 — 리포트에 이양 사실 표기.

### 5.3 오우닝 부서 결정 규칙

1. canonical `department` → 기존 부서 검증(`_assert_known_department` 선례)으로 org_path 매칭.
2. 누락/미매칭 → 오너(인터뷰이)의 employees org_path에서 파생.
3. 둘 다 실패 → NULL(레거시 맵 취급) + 리포트 경고 행.

파급효과(의도적 유지): 오우닝 부서가 설정되면 기존 규칙대로 **부서원 전원이 editor 바닥값**을 파생받는다 — "이양 후 현업 유지보수" 개념과 정합. 비공개 맵이어도 부서원은 열람·편집 가능, 외부인만 명시 뷰어/에디터 필요.

## 6. UI (Phase 2)

> Phase 2 스코핑 확정(2026-08-08): **배치 = Maps 탭 좌측 컬럼 상단 세그먼트 토글(Departments ↔ Framework)** — 탭 증식 없이 같은 맵 공간의 두 렌즈, 우측 대시보드 유지. **스케일 = 신규 표면(카테고리 트리)만 처음부터 서버 주도(lazy 펼침·페이지네이션)로 정합** — 기존 홈 fetch-all·SP 피커 재설계는 별도 "스케일 하드닝" 트랙(대량 전달 도래 전 실행, §8).

- **홈 카테고리 트리 뷰**: L1~L5 트리(빈 카테고리 포함) → L6 맵 행. 펼칠 때 자식 조회(lazy)·맵 목록 페이지네이션 — fetch-all 금지. 체계 맵은 일반 맵이므로 **부서 트리에도 그대로 노출**(이중 노출 — Word 맵처럼 목록에서 빼지 않음).
- **맵 상세 카드**: L1~L5 경로 뱃지 + Input/Output + L6 파라미터(기존 SP 지정 카드 확장 표시).
- **I/O 편집**: SP 지정 폼(설정)에 Input/Output 텍스트 필드 추가 — 이양 후 오너가 유지보수(`SubprocessDesignationIn` 확장).
- **슬롯 이양 액션**: 오너/sysadmin이 `category_id`+`consultant_code`를 다른 맵으로 이전(일반 맵으로 대체 시나리오).
- 카테고리 연결/해제 UI(맵 설정 또는 상세 카드) — 신규 편입·폐기 시나리오 지원.

> **개정(2026-08-12) — 관리자 Framework 탭**: 설정(admin 콘솔)에 sysadmin 전용 **Framework 탭** 추가 — ① 카테고리 트리 직접 관리(생성·개명·이동·삭제, `ui-` 자동 code, 레벨≤5·순환·비어있지 않음 가드) ② **웹 대량 임포트**(`POST /api/categories/import`, categories.json+maps.jsonl 업로드 → dry-run 리포트 → apply). §5의 CLI는 초대형 전달 대안으로 병행 유지. **재임포트 upsert가 UI 카테고리 수정을 덮는 정책은 불변**(전달물=소스 오브 트루스 — 탭에 안내 문구). 플랜: `2026-08-11-framework-admin-ui.md`(git history).

## 7. 구현 페이즈 (각각 스펙→플랜→구현 사이클)

1. **Phase 1** — 스키마(§2) + canonical 계약(§4) + 임포트 스크립트(§5) + pytest(업서트 멱등성·2-pass 연계·버전 적재·오우닝 부서 규칙·dry-run 리포트).
2. **Phase 2** — 홈 카테고리 트리(신설 lazy API로 처음부터 스케일 정합) + 경로 뱃지/I/O 표시·편집 + 슬롯 이양·카테고리 연결 UI(§6). **기존 홈 fetch-all·SP 피커 재설계는 별도 "스케일 하드닝" 트랙으로 분리**(대량 전달 도래 전 실행 — 2026-08-08 스코핑 확정).
3. **Phase 3** — 컨설턴트 실스키마 → canonical 어댑터(스키마 확정 후: 조인·이름→login_id 해석·미매칭 리포트).
4. **병렬 트랙** — 거버넌스 UX([`2026-08-08-governance-ux-design.md`](2026-08-08-governance-ux-design.md)) — 임포트와 독립적으로 구현 가능.

## 8. 스케일 전제 — L5 카테고리 ~3,000 · L6 맵 ~20,000

컨설턴트 추산 규모. 전달은 컨설팅 진행에 따라 점진 증가(초기 수백 → 최종 2만)하므로 임포트가 첫날부터 풀 스케일은 아니지만, 최종 규모가 다음을 강제한다:

| 영역 | 강제 사항 |
|---|---|
| canonical | `maps.jsonl` 스트리밍(단일 JSON은 수백 MB — 메모리 로드 불가). 카테고리 ~수천 행은 단일 JSON 허용 |
| 임포트 | 벌크 인서트 + **청크 커밋**(N맵 단위) + 진행 로그. 재실행 시 무변경 맵 스킵이 곧 중단 재개. 성능 픽스처(생성 1k맵)로 pytest 검증 |
| dry-run | 2만 건 diff는 눈으로 못 읽음 — **요약 stdout + 상세 CSV 파일** 출력 |
| 홈/목록 (Phase 2 선행 조건) | 현재 홈은 맵 전체 fetch 전제 — 2만 맵이면 목록 페이로드만 수 MB. **맵 목록 API 서버 필터/페이지네이션 + 카테고리 트리 lazy-load(펼칠 때 자식 조회) + 검색 우선 탐색** 재설계 필요. 이중 노출 결정은 유지하되 로딩 방식이 바뀜 |
| SP 라이브러리 피커 | 전원 SP 지정 → 2만 개 피커 — 서버 검색/페이지네이션 필요(현재 수십 개 전제) |
| 버전 이력 | 재임포트는 **변경 맵만** 새 버전(전량 클론 방지). 그래도 노드 행 수십만 단위 — postgres 무난, 로컬 sqlite는 부분 데이터로 검증 |
