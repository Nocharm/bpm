# Word 맵 AI 컨설턴트 — 문서→순서도 변환 모드 — 설계

- 날짜: 2026-07-26
- 상태: 사용자 승인 (브레인스토밍 축별 확정)
- 브랜치: `dev` (기준 `a621ef0` — word-map 라이프사이클 + AI 컨설턴트 인터뷰 P1 머지 완료 상태)
- 선행: [AI 컨설턴트 인터뷰 모드](2026-07-23-ai-consultant-interview-design.md) · [Word 맵 섹션 링크](2026-07-18-word-map-section-linking-design.md) · [Word 맵 라이프사이클](2026-07-24-word-map-lifecycle-design.md)

## 1. 배경 · 문제

두 기능이 dev에 합쳐지면서 접점이 생겼다: **word 맵에서도 컨설턴트 진입 버튼(`open-consultant`)이 그대로 노출**되지만, 인터뷰 드래프터는 `start|process|decision|end`만 알아 word 맵의 핵심 가치인 **섹션 노드(문서 앵커 점프 링크)** 없는 일반 순서도만 그린다. 근본적으로 일반 인터뷰(7스테이지)는 "머릿속 프로세스를 끌어내는" 구조인데, word 맵은 **이미 사실의 원천(SOP 문서·섹션 카탈로그 `doc_sections`)이 존재**한다.

**확정 컨셉: word 맵의 컨설턴트 = 문서→순서도 변환 컨설턴트.** 묻기보다 제안 우선 — 문서 구조를 읽고 섹션 노드 중심 초안을 그려오면 사용자가 대화로 교정한다.

## 2. 진입 · 모드 분기

- word 맵에서 `open-consultant` 진입 시 **변환 모드 자동 분기**: 세션 생성 시 맵 `mode`를 보고 `InterviewSession`에 모드를 저장. 신규 컬럼은 `db.py` `_ADDED_COLUMNS` 등록 필수 — `interview_sessions` 테이블은 이미 존재하는 배포(개발서버)가 있어 create_all이 컬럼을 보강해 주지 않는다. 일반 7스테이지 인터뷰는 word 맵에서 제공하지 않는다.
- 일반 맵의 인터뷰 동작은 변경 0.

## 3. word 전용 3스테이지 — 기존 엔진 재사용

`StageDef` 리스트만 word용으로 교체. 체크포인트·되돌리기(revert=superseded)·skip·스테이지 칩("Stage n of 3")·질문 픽커·연속 드래프팅·redraw 등 기계장치는 전부 그대로 쓴다.

| 스테이지 | 역할 |
|---|---|
| **scope** | 그릴 범위(문서 전체 / 특정 섹션 서브트리) 확인 · 이중언어 SOP면 언어 트리(KO/EN) 선택(한 언어뿐이면 질문 생략) · 원본 .docx 업로드 권유(§5) · 범위가 크면 1페이지 안착을 위해 서브트리 분할 제안 |
| **draft** (메인) | 초안 제안 ↔ 교정 루프. 속성(담당자·부서·파라미터)은 전용 스테이지 없이 이 루프의 자유 대화로만 반영 |
| **review** | 최종 점검 — 라벨 톤 + 링크 커버리지 요약("노드 N개 중 M개 문서 링크") 후 종료 |

## 4. 드래프터 계약 — 섹션 매핑 (섹션 우선 + 혼용 허용)

- 제안 노드 스키마에 `section_anchor` 추가, `node_type` 어휘에 `section` 추가. 프롬프트에 **선택된 언어 트리의 섹션 카탈로그**(앵커·번호·제목·레벨)를 주입하고 "문서 섹션에 대응하는 활동은 section 노드, 앵커는 카탈로그 값만" 지시.
- **서버 검증(프롬프트만으론 안 막힘)**:
  - 카탈로그에 없는 앵커 → 소거하고 `process`로 강등. 강등은 조용히 하지 않고 턴 노티스로 표기("2개 활동은 문서 섹션을 못 찾아 일반 노드로 추가했습니다").
  - 섹션 노드 라벨은 서버가 카탈로그 기준 `"{번호} {제목}"`으로 **재구성**(모델 출력 신뢰 안 함) — 내보내기 "첫 공백 토큰=앵커 내부링크" 관례를 항상 보장.
- 문서에 없는 중간 단계·분기는 일반 `process`/`decision` 허용(혼용). start/end는 기존 규칙.

## 5. 입력 소스 — 카탈로그 기본 + 원본 업로드 권장

- **기본**: `doc_sections` 카탈로그만으로 즉시 시작 가능(업로드 마찰 없음) — 구조 수준 제안.
- **권장**: scope에서 원본 .docx 업로드 권유 → **기존 인터뷰 첨부 파이프라인**(python-docx 추출·5종·20MB) 재사용. 본문이 있으면 `INTERVIEW_CONTEXT_BUDGET` 내에서 드래프터 컨텍스트에 주입해 흐름·분기 정밀도 상승. 문서 본문은 기존 첨부 저장 방식 그대로(별도 영속화 없음).

## 6. 프론트 — 적용 경로 · UI

- **적용 경로가 핵심 접점**: 인터뷰 프리뷰/적용은 `buildGraphFromAiProposal` + graph PUT 재사용 중 → **노드 속성 추가 체크리스트대로 `section_anchor`를 AI 변환 2곳(`buildGraphFromAiProposal`·page.tsx `aiNodeToGraphNode`)에 스레딩** — 누락 시 적용 순간 앵커 유실(라이프사이클 C4 교훈과 동일 함정). 값 정규화는 CSV 경로와 대칭 유지.
- 병합 시 **기존 섹션 노드 보존**: 서브프로세스 보존과 동일 패턴(제안에 없는 기존 노드의 앵커·타입 유지).
- consult 화면: word 모드면 스테이지 칩이 3단계로 자동 표시. 프리뷰 캔버스의 section 노드는 기존 일반 렌더로 충분(신규 UI 최소). 1페이지 경계 가이드는 에디터 전용 유지.

## 7. 가드 · 엣지

- **섹션 0인 word 맵**: scope에서 재임포트 안내 후 일반 노드만으로 진행 허용.
- **노드 수 가이드**: 1페이지 기준 ~12±α를 프롬프트에 명시, 초과 시 review에서 분할 제안.
- 세마포어·부하 가드·턴 원자성 등은 기존 인터뷰 인프라 그대로.
