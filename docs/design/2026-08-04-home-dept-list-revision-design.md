# 홈 부서 목록 재조정 (2026-08-04, 개정)

[2026-08-04 홈 부서 가시성·시인성 개선](2026-08-04-home-dept-visibility-design.md)의 **§2(A. 조직도 아코디언 재구성)을 대체**한다. 같은 문서의 §3(B. 카드 최근접속 반전)과 §4(C. 진입 포커스·접힘 영속)는 **그대로 유지**된다.

## 1. 왜 되돌리는가

§2는 부서명을 고정폭 필로 바꾸고, 맵을 가진 행을 sticky 경로 헤더로 만들고, 맵 카드의 들여쓰기를 없앴다. 카드 폭은 실제로 통일됐지만 사용자 평가는 "오히려 난잡"이었고, 원인 네 가지가 모두 지목됐다:

1. **좌변이 계속 튄다** — sticky 행은 들여쓰기를 버리고 컬럼 왼쪽 끝에 붙고 네비 행만 들여써서, 목록을 훑을 때 시작점이 지그재그로 움직인다.
2. **breadcrumb이 윗줄과 중복** — `… Strategy Office /`가 바로 윗줄에 이미 보이는 부모 행을 다시 적는다. 조상이 스크롤 밖으로 나갔을 때만 쓸모 있는데 항상 그려졌다.
3. **구분자가 세 종류** — 한 행에 `…`(생략)·`/`(경로)·`›`(체인)이 섞였다.
4. **부서 행과 카드가 뒤섞임** — 부서 목록만 따로 훑을 수 없다.

1~3은 sticky + breadcrumb + 필 체인이라는 §2의 장치 자체에서 나온다. 그래서 그 장치를 걷어내고 **main의 들여쓰기 트리로 되돌린 뒤**, 목록 가독성을 올리는 규칙 네 가지를 새로 얹는다. 4는 트리와 카드가 한 흐름에 있는 한 남지만, ⑤의 그룹 박스가 경계를 만들어 완화한다.

### R1. 카운트는 태그

`({node.mapCount})` 괄호 표기를 태그(알약)로 바꾼다. `rounded-full bg-surface-alt px-2 py-0.5 text-fine text-ink-tertiary`, `data-id="org-node-count"`. 색은 중립 — 액센트는 선택·활성에만 쓰는 토큰이라 카운트에 쓰지 않는다.

### R2. 펼친 부서는 태그 숨김

행이 열려 있으면 자기 태그를 렌더하지 않는다. 열린 순간 그 부서의 내용(자식 행·자기 카드)이 아래에 다 보이므로 롤업 숫자는 중복이고, 조상 체인을 따라 태그가 줄줄이 남으면 그게 노이즈가 된다. **접힌 행만 태그를 단다** → 아직 열지 않은, 즉 행동 가능한 지점만 숫자를 갖는다.

### R3. 펼친 부서 이름은 회색 톤다운

열린 행의 이름은 `text-ink-tertiary`, 닫힌 행은 현행 `text-ink-secondary`(hover 시 `text-ink`). R2와 합쳐, 지나온 경로는 뒤로 물러나고 아직 안 연 부서가 앞으로 나온다.

### R4. 맵 보유 부서 + 그 카드를 박스로 묶음

자기 맵을 가진 부서를 펼치면 **그 부서의 헤더 행과 자기 카드만** 테두리 박스로 감싼다.

- **박스 헤더가 곧 트리 행이다.** 부서명을 트리 행과 박스 제목에 따로 쓰면 같은 이름이 두 줄 연속으로 나온다 — 하나로 합친다. 헤더는 여전히 토글 버튼이고 chevron·회색·태그 숨김 규칙을 그대로 따른다.
- **박스는 컬럼 풀폭**(들여쓰기 0에서 시작). 계층은 박스 **안쪽** 헤더의 `paddingLeft`로 표현한다. 그래서 **카드 폭이 depth와 무관하게 399px로 고정**된다 — §2가 해결했던 폭 문제를 되돌리지 않기 위한 선택이다.
- **자식 부서는 박스 밖.** 박스가 닫힌 뒤 트리가 이어진다. 박스의 뜻은 "이 부서가 **직접** 가진 맵"으로 고정되고, 박스가 중첩되지 않아 depth마다 카드가 좁아지는 일이 없다.
- **접힌 부서는 박스가 없다** — 감쌀 카드가 없으므로 일반 행 + 태그.
- 박스: `rounded-sm border border-hairline bg-surface-alt p-2`, `data-id="org-group-box"`.

### R5. 자기 맵을 자식보다 먼저

main은 `children → maps` 순이라 박스 헤더와 자기 카드 사이에 손자 카드가 통째로 끼어든다. `maps → children`으로 뒤집는다(§2에서 이미 한 변경을 유지).

### R6. 미지정·내 부서 섹션도 같은 박스

`Unassigned`와 `MyDeptFavorites`는 "부서 하나 + 그 맵"이라는 같은 모양이다. 같은 박스로 그려 좌측 컬럼의 시각 언어를 하나로 맞춘다. 이걸 빼면 내 부서 카드만 417px, 조직도 카드는 399px로 어긋난다.

## 4. 불변식 · 랜드마인

- **박스 헤더 = 트리 행.** 둘을 분리하면 부서명이 두 번 나온다. 새 마크업을 넣을 때 헤더를 따로 만들고 싶어지면 멈출 것.
- **박스는 중첩 금지.** 자식을 박스 안에 넣으면 depth마다 카드가 399 → 375 → 351px로 줄어 §2 이전 상태로 회귀한다.
- **들여쓰기는 박스 안쪽에.** 박스 자체를 들여쓰면 카드 폭이 다시 depth에 묶인다.
- **R2·R3은 `open` 하나로 갈린다** — 태그 유무와 색이 같은 조건을 보므로 조건을 두 벌로 쓰지 말 것.
- **`collectPillChain` 제거 시 테스트도 함께.** `collectSingleChildChain`과 그 테스트(`org-tree.test.ts`의 unconditional chaining)는 자동펼침에 계속 쓰이므로 **건드리지 않는다**.
- **DOM 계약** — 브라우저 스모크가 의존한다. 토글 행은 `data-id="org-node-toggle"` · `data-path` · `aria-expanded`를 **그대로 유지**하고, `data-sticky`는 제거한다. 신설은 `data-id="org-group-box"`(R4 박스)와 `data-id="org-node-count"`(R1 태그) 둘뿐이다.
- **접힌 행은 카운트가 0이어도 태그를 단다** — `keepEmptyPaths`로 살아남은 빈 부서(내 org_path 앵커)가 `⟨ 0 ⟩`을 보여주는 것은 의도된 결과다. "비어 있음"이 정보다.
- **스모크의 sticky 검사 2건은 폐기 대상이다.** `data-sticky` 기반 검사(“map-owning rows are sticky”, “a sticky header pins to the container top”)는 장치가 사라지므로 그룹 박스 검사로 교체한다. 카드 폭 검사는 `[data-id="home-org-accordion"]` 스코프라 그대로 유효하다.

## 5. 검증

| 항목 | 방법 |
|---|---|
| `collectPillChain` 제거 후 회귀 없음 | `npm run test` — `collectSingleChildChain` 테스트 3종 그대로 그린 |
| 린트·타입·빌드 | `npm run lint` · `npx tsc --noEmit` · `npm run build` |
| 카드 폭 depth 무관 동일 | 브라우저 — 조직도 내 전 카드 `getBoundingClientRect().width` 유일값 1개 |
| 좁은 폭 클리핑 없음 | 브라우저 — 뷰포트 1000·1100·1280·1440에서 부서 행 `scrollWidth <= clientWidth` |
| R2 태그 숨김 | 브라우저 — 열린 행에 `org-node-count` 0개, 닫힌 행에 1개 |
| R3 톤다운 | 브라우저 — 열린 행 이름의 computed color가 닫힌 행과 다름 |
| R4 박스 | 브라우저 — 자기 맵 보유 열린 부서마다 `org-group-box` 1개, 그 안에 자기 카드만(자식 행은 박스 밖) |
| 유지분 회귀 없음 | 브라우저 — 첫 진입 조직도 접힘 · 새로고침 접힘 유지 · 카드 호버 반전 |
