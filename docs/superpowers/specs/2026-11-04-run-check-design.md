# 실행 체크(Run) 설계

> 2026-11-04 브레인스토밍 결과. 화면 목업: https://claude.ai/artifact/5ngxKm5G4JJ8go5MesCH3C (v6, 문구는 한국어 목업). 목업은 사용자가 원격으로 폰에서 검토하느라 폰 폭으로 그렸을 뿐이고, 제품은 데스크톱 전용이다(§2).
> 표기: **[결정]** = 사용자가 정한 것, **[판단]** = 설계자가 정하고 사용자에게 보인 것(뒤집을 수 있음), **[빌더]** = 구현자가 정할 것.

## 1. 무엇과 왜

게시된 프로세스맵 위에서 실제 일 한 건(예: "11월 1차 입고 · LOT 2611-07")을 처음부터 끝까지 밟아 가며 노드마다 진행 상태를 표시하고 코멘트를 남기는 기능이다. 지금 BPM은 프로세스를 그리고 버전으로 관리하는 도구라서, 그 맵대로 일이 실제로 어디까지 갔는지, 어디서 막혔는지를 볼 곳이 없다. 실행 체크는 맵을 체크리스트로 쓰게 해 준다. 맵 내용은 건드리지 않는다.

성공한 모습: 현업이 데스크톱에서 맵을 열고 "실행"으로 한 건을 시작한다. 노드를 눌러 시작·완료·문제를 표시하고, 판단 노드에서는 갈래를 고른다. 함께 일하는 사람들이 같은 실행을 보며 지금 갈 수 있는 길과 막힌 곳을 한눈에 안다. 실행 기록은 써도 DB가 끝없이 커지지 않는다.

## 2. 목표 · 비목표 · 반목표

**목표**
- 게시본(과 지난 게시본) 위에서 실행을 시작하고, 노드별 상태·판단 선택·코멘트를 남긴다.
- 상태가 맵 흐름을 따라 자동으로 퍼진다: 앞 단계가 끝나야 열리고, 고르지 않은 갈래는 흐려진다.
- 개인 실행과 공유 실행. 공유 실행은 참여자가 함께 바꾸고 서로 알림을 받는다.
- 기록 양에 끝이 있다: 열린 실행 상한, 방치 자동 중단, 30일 뒤 한 줄 요약, 보존 상한.

**비목표(이번 범위 밖)**
- 폰·태블릿 화면 **[결정, 2026-11-04: 데스크톱만 쓴다고 가정]**. 실행은 기존 맵 화면(데스크톱) 위에 얹는다. 폰용 아래 시트·전체 화면 창은 만들지 않는다.
- 감사 근거·증적 **[결정]**. 그래서 오래 들고 있지 않는다.
- 사진·파일 첨부 **[판단]** (용량이 가장 빨리 느는 곳).
- 노드별 담당자 지정·강제 **[판단]**. 노드의 기존 `assignee`/`assignee_role`은 보여 줄 수는 있어도 실행 권한과 묶지 않는다.
- 홈 화면의 맵을 가로지르는 "내 실행" 목록 **[판단]**. 진입은 맵의 실행 버튼과 알림 딥링크.
- L5 연계 캔버스(framework 맵)에서의 실행 **[판단]**. 게시(published)가 아니라 확정(confirmed) 트랙이라 대상이 아니다.
- 실행 통계 대시보드. 한 줄 요약을 남기는 데서 멈춘다.

**반목표(동작해도 실패인 것)**
- 실행 상태가 맵 내용에 새어 들어가는 것: 노드 색, 버전, 비교 diff, 확정 서명·게이트, 내보내기 어디에도 영향이 없어야 한다 **[판단]**.
- 실행 알림이 결재 알림을 밀어내는 것. BPM 알림은 인당 100개 캡(`backend/app/workflow.py` `NOTIFICATION_CAP`, 읽음 무관 오래된 순 삭제)이라 실행 알림이 많으면 결재 알림이 사라진다.
- 실행 기록이 무한정 쌓이는 것.
- Draft·확인 요청 중·거절 버전에서 실행되는 것(내용이 바뀌는 중이라 기록이 엉킨다).

## 3. 제약

- 운영 DB 리셋 불가. 새 테이블은 기동 `create_all`로 생기지만 기존 테이블에 컬럼을 더하면 `db.py` `_ADDED_COLUMNS` 등록이 필요하다(CLAUDE.md).
- 백엔드는 단일 uvicorn 프로세스, 스케줄러는 `main.py` lifespan의 asyncio 루프(HR 동기화 선례).
- 시각은 KST(`app/clock.now()`), FE 표시는 `lib/datetime`.
- UI는 영어 기본 + ko i18n(design.md §5). 목업 문구는 ko 카피의 출발점.
- 색은 토큰만, 악센트 계열은 `--color-accent`에서 color-mix로 파생(고정 hex 금지). 프리셋·공식을 바꾸면 `scripts/pw-verify-accent-contrast.mjs`.
- 서버는 평문 HTTP: id는 `genId()`.
- 캔버스 작업 전 `docs/lessons/` 해당 카테고리를 읽는다.

## 4. 정해진 것

### 4.1 실행의 대상과 시작

- **버전 [결정]**: 실행은 게시본(`published`) 위에서. 지난 게시본(`expired`)도 허용하되, 시작 전에 "현재 게시본이 아니에요" 안내 창(현재 게시본으로 실행 / 지난 게시본으로 계속)을 거치고, 실행하는 동안 실행 바 위에 안내 줄(현재 버전 열어 보기 링크)이 계속 보인다. 실행 중에 새 게시본이 나와 기준 버전이 지난 게시본이 되면 그때부터 같은 안내 줄이 뜬다 **[판단]**.
- **막힌 버전 [판단]**: Draft·pending·approved(게시 전)·rejected는 실행 버튼이 꺼지고 이유를 툴팁으로 보인다.
- **시작할 수 있는 사람 [결정, 2026-11-04]**: 그 맵을 볼 수 있는 사람이면 누구나(유효 역할 viewer 이상, `permissions/logic.py` `effective_role`). 개인·공유 모두 같다. 근거: 실제로 일하는 현업은 대부분 Viewer다.
- **진입 [결정+판단]**: 맵 화면 위쪽의 "실행" 버튼. 드롭다운은 압축 **[결정]**: 내가 참여한 진행 중 실행 3줄 + 최근 끝난 실행 1줄 + "모든 실행 보기" + "새 실행" **[판단: 줄 수]**.
- **새 실행 창**: 이름(자유 텍스트, LOT 등), 기준 버전, 나만/공유 작은 탭(창 제목 오른쪽) **[결정]**, 공유일 때 참여자 고르기.
- **열린 실행 상한 [결정]**: 개인 실행은 사람당 진행 중 10개(맵 합산), 공유 실행은 맵당 진행 중 30개. 맵당 30에는 공유 실행만 센다 **[판단]**: 남의 개인 실행은 보이지 않아서 같이 세면 보이지도 지울 수도 없는 실행 때문에 막힌다. 넘으면 새 실행 창이 "내가 정리할 수 있는 실행"부터 보여 준다(개인 상한은 맵을 가로질러 내 열린 개인 실행 목록) **[판단]**.

### 4.2 상태 모델

- **저장하는 것 [판단]**: 손댄 노드의 수동 상태(`active` 진행 중 · `done` 완료 · `problem` 문제)와 판단 노드의 선택 엣지만. 나머지는 매번 맵에서 계산한다.
- **계산하는 것**: `waiting` 대기(앞 단계가 남음) · `ready` 진행 가능 · `skipped` 건너뜀(고르지 않은 갈래, 바로 완료한 하위프로세스의 남은 단계, 닫힌 실행의 남은 단계). start 노드는 늘 완료.
- **전이표 [판단, 목업 그대로]**: 사람이 누르는 동작과 그 결과.

  | 지금 상태 | 가능한 동작 → 결과 |
  |---|---|
  | `ready` 진행 가능 | 완료 → `done`(시작을 거치지 않아도 됨) · 시작 → `active` · 문제 있음 → `problem` |
  | `active` 진행 중 | 완료 → `done` · 문제 있음 → `problem` · 시작 취소 → 수동 상태 지움(`ready`로 돌아감) |
  | `problem` 문제 | 문제 해결 → `active` · 완료 → `done` |
  | `done` 완료 | 완료 취소 → 수동 상태와 판단 선택을 지움(아래 취소 규칙) |
  | `waiting` · `skipped` | 동작 없음. 대기는 꺼진 완료에서 먼저 끝낼 단계로 이동(§4.3), 건너뜀은 이유를 보인다 |

  - `done`에서 바로 `problem`으로 가는 길은 없다. 완료 취소 뒤 다시 표시한다.
  - 판단 노드는 갈래 이름 버튼 하나로 `done` + 선택 엣지를 함께 저장한다. 갈래를 바꾸려면 완료 취소 후 다시 고른다.
  - start·end는 직접 누르지 않는다. end는 살아 있는 앞 단계가 모두 완료되면 계산으로 완료된다.
  - 하위프로세스 노드는 위 표에 "하위 맵에서 밟기"가 더해진다(완료 전). 완료 뒤에는 "하위 맵 보기".
  - 진행률의 단계 수는 task · decision · subprocess 노드 중 건너뜀이 아닌 것이다. 하위프로세스는 하나로 센다. 중단된 실행은 중단 전 계산으로 분모를 정한다.
  - 취소를 막는 "뒤 단계를 손댐"은 그 노드에서 엣지를 따라 닿는 노드 중 하나라도 수동 상태나 판단 선택이 있는 경우다. 코멘트는 손댐으로 치지 않는다. 하위프로세스는 하위 맵에 수동 상태가 있으면 바깥의 시작 취소를 막고, 하위 맵 안의 완료 취소는 바깥의 다음 단계를 손댔으면 막는다.
- **유기적 전파 [결정]**: 앞 단계가 안 끝난 노드는 시작도 완료도 막힌다. 판단 노드에서 갈래를 고르면 나머지 갈래와 그 뒤로만 이어지는 노드가 흐려진다.
- **병렬·합류 [판단]**: 병렬 갈래는 동시에 진행할 수 있고, 다시 합쳐지는 노드는 흐려지지 않은 앞 단계가 모두 끝나야 열린다. 계산 규칙: 노드로 들어오는 "살아 있는 엣지"(출발이 건너뜀이 아니고, 판단 노드라면 선택된 엣지)가 하나도 없으면 건너뜀, 있으면 그 출발이 모두 완료일 때 진행 가능. 목업의 `derive()`가 기준 구현이다.
- **갈래 판정은 출력 규칙을 따른다 [판단]**: 어느 출구가 병렬이고 어느 것이 택일인지는 `lib/output-rules.ts` `getOutputGroups`(start 기본 병렬, `parallel_outputs`, 레거시 `gateway="parallel"`)로 읽는다. 출력 규칙(2026-10-01) 이전 버전에 남은 "판단도 병렬도 아닌 갈라짐"은 판단 노드처럼 택일로 다룬다(완료할 때 갈래를 고름). 병렬로 다루면 실제로 택일이던 맵에서 합류 노드가 영영 열리지 않아 실행이 멈추고, 택일로 다루면 최악이라도 한 갈래를 못 체크할 뿐이다.
- **역행 엣지(루프)**: 목업은 루프가 없는 맵만 다뤘다. **[빌더]** 반복 ◇ 처리(예: 루프 엣지는 전파 계산에서 제외하고 판단 선택으로만 다시 열기)를 정하고 문서에 남긴다.
- **취소 [판단]**: 완료 취소는 뒤 단계를 아무도 손대지 않았을 때만. 이미 진행됐으면 어느 단계 때문인지 보여 주고 막는다. 시작 취소도 가능(하위 맵에 기록이 있으면 막음). 문제 → "해결"은 진행 중으로 돌아간다.
- **코멘트 [결정]**: 선택이고 어떤 상태에서도 남길 수 있다. 2,000자 **[판단]**. 첨부 없음.
- **실행 끝 [판단]**: 모든 노드가 완료나 건너뜀이 되는 순간 자동으로 "끝남·완료"가 되고, 그날부터 요약까지 30일을 센다. 택일 흐름에서는 고른 끝에 닿는 것과 같다. 병렬 갈래가 서로 다른 끝으로 가면 모든 끝이 완료돼야 한다. 문제·진행 중·진행 가능 노드가 하나라도 남으면 자동으로 끝나지 않는다. 그런 실행은 시작한 사람이 "중단"하거나(§4.4) 방치 40일 자동 중단이 정리한다.
- **하위프로세스 [결정]**: 바로 완료하거나, 들어가서(캔버스 안 읽기 전용 펼침) 하위 맵 단계를 밟을 수 있다. 하위 맵에서 시작하면 바깥 노드는 진행 중, 하위 맵의 끝에 닿으면 바깥 노드가 자동 완료. 바로 완료하면 하위 맵의 남은 단계는 건너뜀 **[판단]**.
  - 하위 맵 버전 **[판단]**: 에디터의 읽기 전용 임베드와 같은 해석(고정 `linked_version_id` 또는 최신 추종)으로 고르고, 그 실행이 그 하위프로세스를 처음 건드릴 때 실행에 고정한다. 실행 도중 하위 맵이 새로 게시돼도 바뀌지 않는다.
  - 끝이 둘 이상인 하위프로세스 **[판단]**: 하위 맵에서 닿은 끝이 바깥 출구를 정한다(판단 노드의 갈래 선택과 같은 효과). 바로 완료할 때는 어느 출구로 나갈지 고른다.
  - 중첩 깊이 **[빌더]**: 목업은 한 단계만 보였다. 하위의 하위도 같은 규칙으로 들어갈 수 있게 하되 상한은 빌더가 정한다.
- **서버가 진실 [판단]**: 상태 전이(막힘·취소 가능 여부 포함)는 API 경계에서 서버가 다시 판정한다. 공유 실행은 여러 사람이 동시에 바꾸기 때문이다. 그래서 전파 계산은 FE(표시)와 BE(검증) 이중 구현이 되고, `duration.ts`↔`duration.py`처럼 같은 테스트 사례로 맞춘다.

### 4.3 화면

- **실행 바**: 실행 이름, 참여자 아바타, 진행(완료 단계 / 전체 작업 단계, 건너뜀 제외), 영구 보존 책갈피, 오른쪽에 나만/공유 작은 탭 **[결정]**과 실행 메뉴(⋯: 이 실행 알림 끄기 · 실행 중단 / 다시 열기). 실행이 끝나면 "실행 완료" 칩.
- **노드 동작: 모달 없이 버튼 줄 [결정, 2026-11-04]**: 실행 모드에서 노드를 누르면(선택) 창을 띄우지 않고 노드 옆(위, 자리가 없으면 아래)에 그 상태에서 할 수 있는 동작 버튼만 한 줄로 뜬다. 매번 창을 여닫는 피로를 없애고 단계를 가벼운 클릭으로 넘기는 것이 핵심이다. 빈 캔버스를 누르거나 Esc면 닫힌다. 유리 레이어(`glass glass-dense`)와 오버레이 z 사다리를 따른다.
  - 버튼(§4.2 전이표 기준): 진행 가능 = 완료 · 시작 · 문제, 진행 중 = 완료 · 문제 · 시작 취소, 문제 = 해결 · 완료, 완료 = 완료 취소. 하위프로세스는 "하위 맵"(들어가기)이 더해진다. 맨 끝에 코멘트 말풍선(개수).
  - 판단 노드는 버튼 줄에 갈래 이름이 바로 나와서 한 번 눌러 완료와 갈래 선택을 같이 한다 **[판단]**.
  - 문제를 누르면 바로 표시되고, 버튼 줄 아래에 한 줄 메모 칸만 열린다(선택, 건너뛰기·Enter) **[판단]**. 여기 남긴 말이 1분 묶음 규칙(§4.5)으로 문제 알림에 붙는다.
  - 코멘트 목록·입력과 "누가 언제"는 말풍선을 눌렀을 때만 작은 팝오버로 연다 **[판단]**.
  - 완료하면 새로 열린 단계가 하나일 때 선택이 그 노드로 넘어간다(이어서 클릭). 병렬로 여럿 열리면 제자리에 두고 열린 노드만 두 번 반짝인다 **[판단]**.
  - 시작·끝 노드, 건너뜀 노드, 닫힌 실행은 동작 없이 짧은 안내만(닫힌 실행도 말풍선으로 코멘트는 읽는다).
- **막힌 노드 → 먼저 끝낼 단계로 이동 [결정, 2026-11-04]**: 대기 노드의 버튼 줄에는 완료가 꺼진 채(aria-disabled라 호버·클릭은 받음) 보인다. 올려 두면(키보드 포커스·클릭도 같음) 작은 팝오버에 "먼저 끝내야 할 단계"가 상태 필과 함께 뜨고, 누르면 그 노드로 이동한다. 이동은 에디터의 기존 포커싱을 재활용한다: 선택 + 화면 밖일 때만 현재 줌으로 가운데로(`revealNodeIfOffscreen`, 연속 이동은 `getFocusAnchorZoom` 앵커 줌, 임베드 자식이면 `childNodes` 선택 규칙은 Tab 흐름 이동과 같게). 이동해 온 노드는 두 번 반짝인다.
  - 보여 줄 단계 **[판단]**: 바로 앞 단계가 아니라, 살아 있는 엣지를 거슬러 올라가 처음 만나는 "지금 손댈 수 있는" 노드(진행 가능·진행 중·문제)들이다. 바로 앞도 대기라면 거기로 가 봐야 또 막혀 있기 때문이다. 팝오버가 열린 동안 그 노드들에 점선 테두리를 그린다. 목업 `getFrontier()`가 기준이다.
  - 팝오버 자리 **[판단]**: 노드 아래 → 오른쪽 → 왼쪽 → 버튼 줄 위 순서. 갈 곳 노드를 덮지 않게 옆자리를 먼저 쓴다.
- **상태 색 [결정: A안 색칠]**: 노드 채움과 테두리로 상태를 보인다. 진행 가능·진행 중은 테마색 그대로, 완료·문제는 초록(`--color-added`)·빨강(`--color-error`)에 테마색을 섞는다 **[결정]**. 섞는 비율 22% **[판단]**: 더 섞으면 플럼 테마에서 문제와 진행 중이 가까워진다. 대기·건너뜀은 회색에 테마색 6%. 상태 배지 아이콘(진행 중 ▶, 완료 ✓, 문제 !, 대기 자물쇠). 목업 `buildStatusPalette()`가 공식 원본이다. 제품에서는 토큰(`color-mix`)으로 옮긴다.
- **연결선 [결정: E1]**: 지금 갈 수 있는 길(진행 가능·진행 중 노드로 들어가는 엣지)에만 점이 흐른다. 실행 화면에서는 설계용 흐름 펄스(`lib/edge-pulse.ts`)를 끈다. 엣지 종류 5가지(우선순위 순): 건너뜀(흐린 회색) > 앞이 안 끝남(옅은 테마 회색) > 문제로 들어감(문제 색) > 지금 갈 길(테마색, 흐르는 점) > 지나온 길(완료 색). 흐르는 점은 `stroke-dasharray: 0.01 10` + 둥근 끝 + `stroke-dashoffset` 애니메이션, 모션 축소면 멈춘다. 목업 `getEdgeKind()`가 기준이다.
- **범례**: 상태 범례와 연결선 범례(목업 사이드 패널).
- **모든 실행 창 [결정: 더보기 → 새 창]**: 진행 중 · 끝남 · 요약 세 탭, 이름·LOT 검색, "내가 참여한 것만"·"영구 보존만" 거르기, 8줄씩 쪽 나눔 **[판단]**. 기존 모달 컨벤션(`ModalBackdrop`, mousedown 기준 닫기·Esc)을 따른다. 끝난 실행 줄에는 "23일 뒤 요약만 남음"처럼 남은 날을 보인다.

### 4.4 개인·공유와 권한

- **개인 실행**: 만든 사람만 본다 **[판단]**(맵 오너·sysadmin도 보지 않는다).
- **공유 실행**: 참여자만 상태를 바꾸고 코멘트한다 **[결정: 상태 / 판단: 코멘트]**. 맵을 볼 수 있는 다른 사람은 목록에서 보고 열어서 진행 상황을 읽기만 한다.
- **참여자 후보 [판단]**: 그 맵을 볼 수 있는 사람(`permissions/access.py` `get_eligible_users`, 담당자·승인자 후보와 같은 집합). 시작한 사람은 실행 중에도 참여자를 더하고 뺄 수 있다 **[판단]**. 뺀 사람이 남긴 기록은 이름과 함께 남는다.
- **접근을 잃은 사람 [판단]**: 협업자에서 빠지거나 맵이 비공개로 바뀌어 맵을 못 보게 되면 그 실행도 못 연다. 남긴 기록은 그대로 남고, 알림은 더 가지 않는다.
- **나만 → 공유 [결정]**: 실행 중에 바꿀 수 있다. 바꿀 때 참여자를 고르고, 고른 사람에게 초대 알림. 맵의 공유 실행이 이미 30개면 막힌다 **[판단]**. 공유 → 나만은 안 된다 **[판단]**: 다른 사람이 남긴 기록과 받은 알림이 주인 없이 남는다.
- **중단 [결정]**: 실행을 시작한 사람만. 실행 메뉴에서 한 번 확인 후 중단. 중단하면 실행 바 아래 "중단된 실행" 줄과 "다시 열기", 실행은 읽기 전용, 남은 단계는 흐려지되 문제 표시는 기록으로 남는다.
- **다시 열기·삭제 [판단]**: 시작한 사람만. 맵 오너의 삭제 권한은 두지 않는다. 시작한 사람이 손을 놓아도 40일 자동 중단이 정리한다.
- **영구 보존 켜기·끄기 [판단]**: 공유 실행은 시작한 사람과 맵 오너, 개인 실행은 본인.

### 4.5 알림

- **보내는 때 [결정: 공유 실행의 다른 참여자에게 / 판단: 종류]**: 단계 완료, 문제 표시, 문제 해결, 실행 끝남·중단, 초대(공유 시작·전환·참여자 추가), 방치 30일. 행동한 사람 본인에게는 가지 않는다. 개인 실행은 방치 30일 알림만 본인에게.
- **묶기 [판단]**: 같은 실행의 완료는 한 줄로 묶는다("박서연 님 외 1명이 단계 3개를 완료했어요 · 최근: 시료 채취"). 문제는 하나씩 따로 보낸다. 묶는 창(예: 수신자가 아직 읽지 않은 같은 실행의 완료 알림이 있으면 그 행을 갱신)은 **[빌더]**.
- **코멘트 [판단]**: 코멘트만으로는 알림이 없다. 문제를 표시하고 1분 안에 같은 사람이 남긴 코멘트는 그 문제 알림에 붙는다.
- **끄기 [판단]**: 실행 메뉴에서 실행별로 알림 끄기(참여자별 설정).
- **결재 알림 보호 [판단]**: 인당 100개 캡을 넘어 지울 때 실행 알림(run 계열 유형)을 먼저, 오래된 순으로 지운다. 실행 알림이 하나도 안 남았을 때만 지금처럼 다른 알림을 지운다. `create_notifications`의 트리밍 한 곳만 바뀌고 테이블·종 아이콘·미읽음 배지는 그대로다. 기존 유형의 동작이 바뀌지 않는 것을 테스트로 고정한다.
- 새 알림 유형은 payload · FE `lib/notification-format.ts` KNOWN_TYPES · i18n · 아이콘 4곳을 같이 등록한다. 클릭하면 그 실행으로 딥링크.

### 4.6 보존과 정리

- **방치 [결정]**: 마지막 손댄 날(상태 변경·코멘트) 기준 30일에 참여자 알림("10일 안에 손대지 않으면 자동으로 중단돼요"), 40일에 자동 중단. 자동 중단도 직접 중단과 같이 "끝난 실행"으로 간다.
- **끝난·중단된 실행 [결정]**: 30일 동안 다른 액션이 없으면 단계별 기록·코멘트·로그를 지우고 한 줄 요약만 남긴다. 그 30일을 다시 세는 "다른 액션"은 다시 열기뿐이다 **[판단]**(열어 보기만으로 늘면 가끔 들여다보는 실행이 영영 안 지워진다). 다시 열면 진행 중으로 돌아가고, 다시 끝난 날부터 30일을 새로 센다. 요약 전 알림은 없고 목록에 남은 날만 보인다 **[판단]**.
- **한 줄 요약 [판단]**: 이름, 결과(완료·중단), 기간("9월 12일~14일(3일)" / "9월 21일 하루"), 기준 버전, 문제 있었던 단계 수, 참여자("박서연 외 2명"). 지우지 않고 계속 남긴다: 건당 약 0.5KB로 1년에 몇 MB 수준이고, 맵이 몇 번 돌았고 실제로 며칠 걸렸는지를 맵의 소요시간 파라미터와 견줘 볼 근거가 된다. 요약이 된 실행은 다시 열 수 없다.
- **영구 보존 [결정]**: 진행 중이든 끝난 뒤든 실행 바나 모든 실행 창의 책갈피로 켠다. 켜 두면 끝난 뒤에도 요약으로 줄이지 않는다. 방치 40일 자동 중단은 그대로 적용되지만 기록은 남는다 **[판단]**. 끄면 그날부터 30일 뒤 요약 **[판단]**.
- **보존 상한 [판단]**: 공유 실행은 맵당 50개. 개인 실행은 맵 상한에 세지 않고 사람당 10개(맵 합산)로 따로 센다. 남의 개인 실행이 보이지 않는 것은 열린 실행 상한과 같은 이유다.
- **요약을 보는 사람 [판단]**: 공유 실행의 요약은 그 맵을 볼 수 있는 사람이 "요약" 탭에서 본다. 개인 실행의 요약은 만든 사람만 본다. 맵 오너에게도 보이지 않는다.
- **숫자 조정 [판단]**: 30·40·30일과 10·30·50개 상한은 sysadmin이 설정에서 바꿀 수 있다(`app_settings`). 위치·화면은 **[빌더]**.
- **하루 한 번 정리 [판단]**: 새벽(KST, DB 백업 04:00과 겹치지 않게) 정리 잡이 방치 알림·자동 중단·요약 전환을 처리한다. HR 동기화처럼 lifespan 루프로 돌고, 결과는 `app/batch_runs.py` `record_batch_run`으로 기록해 설정 Batch jobs 탭(`components/admin/batch-runs-panel.tsx` JOBS)에 DB 백업·HR 동기화와 나란히 보인다.
- **맵과 함께 [판단]**: 맵을 휴지통에 넣으면 실행도 숨고, 영구 삭제하면 같이 지워진다(FK cascade).
- **쌓이는 양(추정)**: 단계별 기록은 진행 중 + 끝난 지 30일 안 된 실행에만 있어 "한 달치 사용량"에서 멈춘다. 하루 20건이면 상세 기록 약 12MB, 요약은 1년에 약 4MB, 영구 보존은 맵당 50개로 맵 하나에 1MB 남짓.

### 4.7 맵과의 분리

- 실행은 맵 그래프와 별도 테이블에 저장한다. 노드 색·버전·비교·확정 판정·내보내기·서명 어디에도 들어가지 않는다 **[판단]**.
- 실행은 `version_id` + 그 버전의 노드 id·엣지 id를 가리킨다. 게시본은 바뀌지 않으므로 id가 안정적이다(노드 id는 전역 PK).

## 5. 빌더에게 맡기는 것

- 테이블 설계(실행 · 참여자 · 노드 상태 · 코멘트 · 로그 · 요약 필드), 인덱스, API 모양. 제약은 §4.2의 "작게 저장"과 §4.6의 정리 단위.
- 기존 맵 화면에 실행을 얹는 방법(읽기 전용 보기 위 실행 모드, URL에 실행 id를 실어 알림 딥링크가 바로 열리게). 맵 화면 `frontend/src/app/maps/[mapId]/page.tsx`는 약 12,500줄 단일 컴포넌트라 실행 상태를 메인 state에 섞지 않고 별도 모듈·컴포넌트로 둔다(`docs/lessons/react-ts-patterns.md`). 실행 모드에서는 편집 동작(드래그·연결·우클릭 편집 메뉴)이 꺼져야 한다.
- 공유 실행의 다른 사람 변경을 화면에 반영하는 방식(폴링 주기 등)과 동시 변경 충돌 처리(서버 판정 실패 시 최신 상태로 새로고침).
- 루프 처리, 하위프로세스 중첩 상한, 완료 알림 묶기 창.
- 영어 UI 문구와 ko 번역(용어 통일표: 게시본 · 오너 · Draft · 승인자를 따른다), `data-id` 부여, 아이콘(Lucide).
- 정리 잡의 정확한 시각과 실패 재시도.
